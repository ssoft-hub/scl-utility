# Замеры группы Runtime

- Набор замеров: `benchmark/runtime/`
- Настройка: `cmake --preset <preset> -DSCL_BUILD_BENCHMARKS=ON`
- Цель замера времени: `utility_runtime_gbench`
- Цель замера размера: `utility_runtime_size`

## О чём эта страница

На странице показано, сколько стоит один вызов каждого шаблона функции группы, что определяет эту
стоимость и какой атрибут оптимизации оправдан в коде группы. Атрибут, который ускоряет вызов, может
увеличить код, поэтому рядом со временем измеряется размер той части группы, которая собирается
для системы без ОС.

## Метод

### Пары

Каждый вариант сравнивается с базой, собранной из тех же исходников в том же раунде. База
запускается в каждом раунде дважды, первой и последней, а раунды идут один за другим,
и поэтому прогрев машины за час сказывается на обоих членах каждой пары.

Разница между двумя запусками базы составляет нулевой канал. Два запуска одного исполняемого файла
должны совпадать, поэтому всё, что их разделяет, задаёт порог, ниже которого разница ничего
не значит. Вариант учитывается, только если значение случая смещается в одну сторону во всех раундах
и больше, чем на 90-й процентиль нулевого канала своего компилятора.

### Настройки

Каждый случай выполняется 15 повторениями не короче 0,5 секунды, а значением случая служит медиана
повторений. Для каждого компилятора выполняется 4 раунда. В Windows процесс привязан к одному
логическому процессору и запущен с высоким приоритетом. В Linux, под WSL 2 на той же машине, процесс
привязан командой `taskset` и сохраняет обычный приоритет.

| Система | Компилятор | Библиотека | Флаги |
|---|---|---|---|
| Windows | GCC 13.1 (MinGW) | libstdc++ | `-O3`, `-std=gnu++20` |
| Windows | Clang 22.1 | MSVC | `-O3`, `-std=gnu++20` и `-std=gnu++26` |
| Windows | MSVC 19.44 | MSVC | `/O2 /Ob2`, `/std:c++20` и `/std:c++latest` |
| Linux | GCC 16.0.1 | libstdc++ | `-O3`, `-std=c++20` и `-std=c++26` |
| Linux | Clang 22.1 | libstdc++ | `-O3`, `-std=c++20` и `-std=c++26` |

У GCC 13.1 нет режима C++26. В режиме C++23 каждый макрос атрибута модуля раскрывается у каждого
компилятора так же, как в C++20, поэтому в режиме C++23 компилируется тот же код, что и в C++20,
и этот режим отдельно не измеряется. В Linux оба компилятора используют `<cxxabi.h>`, а в Windows
его использует только GCC, и в Linux измеряются применённые в группе атрибуты и хранилище
восстановленных имён.

| Случай | Что вызывается |
|---|---|
| `type_name_dynamic` | `type_name(obj)` для объекта производного класса, полученного через ссылку на базовый класс |
| `type_name_template` | то же для объекта специализации шаблона класса |
| `type_short_name_dynamic` | `type_short_name(obj)` для объекта из `type_name_dynamic` |
| `type_short_name_template` | `type_short_name(obj)` для объекта из `type_name_template` |
| `enum_string_decimal` | `enum_string(value)` для значения -3 базового типа `int` |
| `enum_string_decimal_wide` | `enum_string(value)` для наименьшего значения `std::int64_t` |
| `enum_string_format` | `enum_string(value, format)` с функциональным объектом, записывающим число в шестнадцатеричном виде |

| Случай | GCC 13.1 | Clang 22.1 | MSVC 19.44 | GCC 16.0.1, Linux | Clang 22.1, Linux |
|---|---|---|---|---|---|
| `enum_string_decimal` | 5,9 | 6,0 | 13,6 | 6,3 | 9,3 |
| `enum_string_decimal_wide` | 61,3 | 64,2 | 71,9 | 40,0 | 38,3 |
| `enum_string_format` | 10,4 | 8,9 | 19,0 | 11,6 | 14,4 |
| `type_name_dynamic` | 42,7 | 47,9 | 49,6 | 18,6 | 21,4 |
| `type_name_template` | 43,3 | 48,0 | 49,5 | 18,6 | 20,9 |

которое даёт `typeid`, и ничего не восстанавливает.

## Что определяет стоимость

| Свойство | Измеренная альтернатива |
|---|---|
| Поиск последнего `::` в имени останавливается на нём, если по пути не стоит склеенный символ оператора вроде `->>`, и отдельно разбирает только кавычку и угловую скобку | поиск, проверяющий каждый символ: у Clang один поиск в имени из нескольких десятков символов занимает 421-454 нс вместо 20-41 нс |
| `enum_string` записывает число функцией `std::to_chars` в буфер на стеке | `std::format`: у Clang вызов занимает примерно вдвое больше времени, а код Cortex-M4 занимает 15130 байт вместо 1398 |
| Короткое имя перечисляемого типа является константой `enum_string` | короткое имя, вычисляемое при каждом вызове: в 2,3-4,5 раза больше времени на вызов |
| Восстановленное имя хранится там, где есть `<cxxabi.h>` | восстановление имени при каждом вызове, ниже |

Хранилище восстановленных имён в сравнении с восстановлением имени при каждом вызове:

| Случай | GCC 13.1 | GCC 16.0.1, Linux | Clang 22.1, Linux |
|---|---|---|---|
| `type_name_dynamic` | **-82,1%** | **-92,3%** | **-91,2%** |
| `type_name_template` | **-85,1%** | **-93,6%** | **-93,0%** |
| `type_short_name_dynamic` | **-92,1%** | **-92,4%** | **-90,2%** |
| `type_short_name_template` | **-90,8%** | **-90,2%** | **-86,0%** |

Хранилище одно на всю программу, находится под `std::mutex` и никогда не разрушается,
поэтому деструктор, который выполняется после возврата из `main`, по-прежнему его читает. Ключом
служит искажённое имя, а не адрес объекта `type_info`, который может занять библиотека, загруженная
после выгрузки другой. Каждый поток хранит имена в восьми ячейках без деструктора. Ячейка выбирается
по адресу типа, а совпадение проверяется по этому адресу и по адресу искажённого имени. Поток
захватывает блокировку только для имени, которого нет в его ячейке. Ячейки в сравнении с хранилищем
под одной только блокировкой:

| Случай | GCC 13.1 | GCC 16.0.1, Linux | Clang 22.1, Linux |
|---|---|---|---|
| `type_name_dynamic` | **-44,6%** | **-63,6%** | **-62,5%** |
| `type_name_template` | **-45,9%** | **-62,1%** | **-58,9%** |
| `type_short_name_dynamic` | **-60,3%** | **-59,9%** | **-56,7%** |
| `type_short_name_template` | **-53,0%** | **-46,9%** | **-35,7%** |

Две другие формы хранилища не используются:

- Контейнер `std::unordered_map` в каждом потоке, объявленный `thread_local`, разрушается
  раньше каждого объекта, который поток создал до первого вызова, и раньше каждого статического
  объекта, поэтому деструктор такого объекта не может запросить имя. К тому же у GCC в MinGW процесс
  падает, когда завершаются потоки, владеющие объектом `thread_local` с деструктором.
- `std::shared_mutex` вместо `std::mutex` замедляет вызов на 8-25% в Linux и в 1,9-2,4 раза
  у GCC 13.1, потому что для такого короткого поиска разделяемая блокировка стоит дороже обычной.
  С библиотекой `libwinpthread-1.dll` из MSYS2, которую поставляет и Git for Windows, одна
  разделяемая блокировка занимает 1300 нс.

## Обмен скорости на размер

Незаданный буфер делает код и быстрее, и меньше, поэтому выбирать между скоростью и размером здесь
не нужно. Предварительное определение `SCL_INDETERMINATE` ничего не меняет, потому что буфер
объявлен без инициализатора, а макрос лишь выражает это намерение атрибутом `[[indeterminate]]` там,
где компилятор его поддерживает.

Принудительное встраивание вспомогательной функции соединения стоит 28 байт на каждое место вызова
`enum_string` и сокращает время вызова. Если байты важнее наносекунд, следует заранее определить
`SCL_FORCE_INLINE` как `inline`. При таком определении каждая принудительно встраиваемая функция
занимает меньше байт.
