# Any

`scl::any` - контейнер, который хранит одно значение любого типа: создаёт его, держит и
разрушает вместе с собой. Тип `scl::any` не параметризуется типом вложенного объекта,
поэтому одна и та же переменная в разное время хранит объекты разных типов.

- Заголовок: `#include <scl/utility/any/any.h>`

## Обзор

Ту же задачу - хранение одного объекта произвольного типа - решает стандартный тип
`std::any`. Его применимость ограничена двумя условиями, которые выполняются не в любой
сборке.

Во-первых, объект типа `std::any` определяет тип вложенного объекта через значение
`typeid`, то есть использует информацию о типах времени выполнения (RTTI). Если проект
собирается с ключом `-fno-rtti`, то использовать тип `std::any` не получится.

Во-вторых, ни одна операция с объектами типа `std::any` не выполняется в константных выражениях.

Ни одного из этих двух условий тип `scl::any` не требует. Типы он различает не через
значение `typeid`, а через значение [`scl::type_key`](../meta/type_key.md) - уникальный
объект, который библиотека создаёт по одному на каждый используемый тип и определяет его на
этапе компиляции.

Тип `scl::any` доступен в сборках без RTTI, а конструирование, `emplace`, `any_cast`,
`reset` и разрушение выполняются в том числе и в константных выражениях.

Размер `sizeof(scl::any)` равен двум указателям. Столько же занимает тип `std::any` в
libstdc++; в libc++ он занимает вдвое больше, а в реализации MSVC - вчетверо. Поэтому с любой
из этих стандартных библиотек замена типа `std::any` на тип `scl::any` не увеличивает размер
объекта, а с libc++ и с реализацией MSVC уменьшает его.

Вложенный объект типа `T` размещается непосредственно внутри объекта типа `scl::any`, без
обращения к аллокатору, если он удовлетворяет трём условиям: помещается во встроенный
буфер, не требует выравнивания строже указателя и имеет конструктор перемещения, не
выбрасывающий исключений. Объект, который этим условиям не удовлетворяет, контейнер
размещает в сегменте памяти, полученном от аллокатора. Выбор между двумя способами
размещения делается для каждого типа на этапе компиляции.

Тип вложенного объекта должен иметь публичный деструктор, который не выбрасывает
исключений, а также публичный конструктор, пригодный для создания объекта из переданных
аргументов.

Если объект типа `scl::any` содержит вложенный объект, не имеющий конструктора перемещения,
то такой вложенный объект размещается в сегменте памяти, выделенной с помощью аллокатора.
При перемещении объекта типа `scl::any` указатель на вложенный объект передаётся новому
контейнеру, а сам вложенный объект остаётся на месте.

Если объект типа `T` не имеет конструктора копирования, то такой объект тоже можно
разместить внутри объекта типа `scl::any`. Копирование у типа `scl::any` не выполняют ни
конструктор, ни оператор присваивания: копию запрашивает функция `scl::any::try_copy()`, и
создаётся она только при наличии конструктора копирования у вложенного типа. В остальных
случаях контейнер остаётся пустым.

В параметрах шаблона для типа `scl::basic_any<Allocator, Capacity>` задаётся тип аллокатора
и размер встроенного буфера, в котором могут быть размещены подходящие по характеристикам
вложенные объекты. Тип `scl::any` определён как `basic_any<>`, то есть имеет аллокатор
`std::allocator<std::byte>` и буфер размером с указатель.

## Возможности

- Хранит объект любого типа, который имеет деструктор, не выбрасывающий исключений.
- Не использует механизм RTTI.
- Занимает два указателя - столько же, сколько `std::any` в libstdc++.
- Все операции над вложенным объектом, включая конструирование, `emplace`, `any_cast` и
  разрушение, доступны в константных выражениях начиная с C++20.
- Размещает объект подходящего размера непосредственно внутри, не обращаясь к аллокатору.
- Принимает аллокатор параметром шаблона, в том числе аллокатор с состоянием, например
  `std::pmr::polymorphic_allocator`.
- Имеет конструктор перемещения и не имеет конструктора копирования. Копию вложенного
  объекта другого контейнера, а также объекта, на который ссылается представление
  [`any_view`](any_view.md), [`any_mutable_view`](any_mutable_view.md) или аргумент
  [`any_arg`](any_arg.md), запрашивает функция `scl::any::try_copy()`; если у типа этого
  объекта нет конструктора копирования, то контейнер остаётся пустым.
- Наличие конструктора копирования у вложенного типа заранее сообщает метод
  `is_copyable()`.
- Конструктор перемещения, оператор перемещающего присваивания, а также методы `swap()` и
  `reset()` не выбрасывают исключений.
- Возвращает указатель на вложенный объект по вызову функции `any_cast<T>(any *)`; при
  несовпадении типа функция возвращает значение `nullptr` и не выбрасывает исключений. Для
  указателя на неконстантный объект типа `scl::any` возвращается неконстантный указатель,
  через который вложенный объект можно изменить.
- Возвращает значение или ссылку по вызову функции `any_cast<T>(any &&)`, а при несовпадении
  запрошенного типа `T` с типом вложенного объекта выбрасывает исключение
  `scl::bad_any_cast`.
- Преобразуется в представления [`any_view`](any_view.md),
  [`any_mutable_view`](any_mutable_view.md) и в аргумент [`any_arg`](any_arg.md), которые
  ссылаются на вложенный объект, а не на сам контейнер.
- Может быть аргументом метода `apply` объекта [`any_switch`](any_switch.md).
- Не принимает массив ни в конструкторе, ни в присваивании; исключение составляет массив
  константных символов, то есть тип строкового литерала.

## Справочник по API

### Конструирование

```cpp
scl::any empty{};                                 // ничего не хранит
scl::any number{42};                              // размещён в any без обращения к аллокатору
scl::any text{std::string{"Hello Any!"}};         // размещён в выделенной аллокатором памяти
scl::any built{std::in_place_type<std::string>, 3U, 'x'};  // строит "xxx" без временного объекта
scl::any made = scl::make_any<std::string>(3U, 'x');       // то же самое через scl::make_any
```

Конструктор типа `scl::any`, принимающий в качестве аргумента значение, применяет к типу
аргумента операцию `decay`, как это делает и тип `std::any`. Поэтому строковый литерал
хранится как значение `char const *`, а имя функции - как указатель на функцию.

Массив контейнер не принимает. Операция `decay` превратила бы его в указатель на первый
элемент, а указатель владения не даёт: сам массив остался бы вне контейнера, и его время
жизни контейнер не продлевает. Исключение составляет одномерный массив константных
символов, то есть тип строкового литерала: литерал имеет статическую продолжительность
хранения, поэтому указатель на его первый элемент действителен всё время работы программы.
Любой другой массив, включая массив массивов, отвергается на этапе компиляции - и
конструктором, и присваиванием, и формой с `std::in_place_type`, и методом `emplace`, - а
через представление оставляет контейнер пустым. Чтобы контейнер владел элементами, массив
необходимо передать в виде типа `std::array`.

Тип строкового литерала не отличим от типа любого другого массива константных символов, так
что массив `char const [3]` с автоматической продолжительностью хранения контейнер тоже
принимает и хранит как указатель на его первый элемент. Такой указатель переживает свой
массив, и следить за этим должна вызывающая сторона.

Форма конструктора типа `scl::any` с первым параметром в виде значения `std::in_place_type`
конструирует вложенный объект сразу в контейнере на основе переданных аргументов и не
создаёт временный объект. Соответственно, эта форма конструктора позволяет разместить в
контейнере объект типа, который нельзя переместить.

Аллокатор передаётся аргументом в конструктор типа `scl::any` вместе с тегом
`std::allocator_arg`:

<!-- snippet: example/any/owning/any_owning_example.cpp allocator -->
```cpp
static void show_allocator()
{
    ::std::pmr::monotonic_buffer_resource resource;
    using pmr_any = ::scl::basic_any<::std::pmr::polymorphic_allocator<::std::byte>>;

    pmr_any value{::std::allocator_arg, ::std::pmr::polymorphic_allocator<::std::byte>{&resource}};
    value.emplace<::std::string>(64U, 'x');

    ::std::cout
        << "  allocated from the given resource? " << (value.get_allocator().resource() == &resource) << '\n'; // 1

    // The allocator travels with the object: what one allocator acquired, only
    // that allocator may release.
    pmr_any const taken{::std::move(value)};
    ::std::cout << "  and travels with it? " << (taken.get_allocator().resource() == &resource) << '\n'; // 1
}
```

### Чтение и запись

```cpp
scl::any value{42};

if (auto * number = scl::any_cast<int>(&value))   // int *: возможно изменение объекта
    *number = 7;

scl::any const frozen{42};
scl::any_cast<int>(&frozen);                      // int const *: возможно только чтение
scl::any_cast<double>(&value);                    // nullptr: тип не совпал
scl::any_cast<int>(value);                        // 7, возвращает копию значения
scl::any_cast<double>(value);                     // выбрасывает исключение scl::bad_any_cast
```

Форма функции `scl::any_cast` с параметром в виде указателя возвращает значение `nullptr`,
когда запрошенный тип не совпадает с типом вложенного объекта, и не выбрасывает исключений.
Форма функции `scl::any_cast` со ссылкой в случае несовпадения типов выбрасывает исключение
`scl::bad_any_cast`. Форма со ссылкой объявлена только при значении макроопределения
[`SCL_HAS_EXCEPTIONS`](../preprocessor/exceptions.md), равном `1`.

Квалификаторы вложенного объекта соответствуют квалификаторам самого объекта типа
`scl::any`. Из константного объекта типа `scl::any` функция `scl::any_cast` возвращает
указатель на константный вложенный объект, из неконстантного - указатель на неконстантный.
Этим контейнер отличается от представлений [`any_view`](any_view.md),
[`any_mutable_view`](any_mutable_view.md) и аргумента [`any_arg`](any_arg.md), которые
хранят квалификаторы объекта, на который ссылаются, рядом с самим значением.

### Замена и очистка

```cpp
scl::any value{42};

value = std::string{"Hello Any!"};      // разрушает int, сохраняет строку
value.emplace<std::string>(3U, 'x');    // конструирует строку из аргументов по месту
value.reset();                          // разрушает объект, оставляет any пустым
```

Оператор присваивания вложенного типа при замене не вызывается никогда, как и в реализации
`std::any`: прежний вложенный объект разрушается, а новый конструируется заново.

Два способа замены, присваивание значения и вызов метода `emplace`, различаются порядком
действий, и от этого порядка зависит их поведение при исключении.

Присваивание значения сначала получает новое значение и только затем разрушает прежний
вложенный объект. Поэтому конструктор, выбросивший исключение, оставляет прежний вложенный
объект нетронутым. Метод `emplace` разрушает прежний вложенный объект первым, поэтому
конструктор, выбросивший исключение, оставляет объект типа `scl::any` пустым. Такую же
гарантию даёт метод `std::any::emplace`.

От порядка действий зависит и то, каким может быть аргумент. Метод `emplace` читает свои
аргументы уже после того, как прежний вложенный объект разрушен. Если аргумент указывает
внутрь прежнего объекта, то есть на сам объект, на его член или на то, чем он
распоряжается, то метод `emplace` прочитает разрушенное значение. Присваивание значения
читает такой аргумент, пока прежний вложенный объект ещё существует:

```cpp
struct owner
{
    std::unique_ptr<payload> held;
};

scl::any value{owner{std::make_unique<payload>()}};

// Присваиваемое значение лежит внутри вложенного объекта, которым владеет контейнер.
value = *scl::any_cast<owner>(&value)->held;
```

Присваивание контейнеру его же собственного значения не выполняет никаких действий. Это
верно и для присваивания значения, и для присваивания копии, запрошенной по представлению
[`any_view`](any_view.md), которое ссылается на вложенный объект этого самого контейнера:

```cpp
scl::any value{std::make_unique<int>(42)};

value = scl::any::try_copy(scl::any_view{value});   // ничего не происходит
```

Такое поведение сохраняет значение типа, у которого нет конструктора копирования: копию
получить нельзя, а замена оставила бы контейнер пустым. Если же представление ссылается не
на сам вложенный объект, а на его **член**, то тип этого члена отличается от типа вложенного
объекта, и выполняется обычная замена.

Указатели внутрь вложенного объекта после замены и после вызова метода `reset()`
использовать нельзя, поскольку объект, на который они указывали, разрушен.

### Повторное использование памяти

Замена вложенного объекта на другой сохраняет уже выделенную память при двух условиях: этот
блок вмещает новый объект, и сам новый объект не может быть размещён во встроенном буфере.
Тогда аллокатор не вызывается ни для освобождения, ни для нового выделения: новый объект
конструируется в том же блоке, размеченном под его собственные размер и выравнивание,
поэтому его адрес не обязан совпадать с адресом прежнего.

```cpp
pmr_any value{std::allocator_arg, pmr_allocator{&resource}};
value = three_doubles{1.0, 2.0, 3.0};                        // одно выделение памяти

for (int round = 0; round < 16; ++round)
    value = three_doubles{double(round), 0.0, 0.0};           // выделений памяти больше нет
```

Такое повторное использование заметнее всего там, где освобождение памяти ничего не
возвращает. Ресурс `std::pmr::monotonic_buffer_resource` не выдаёт освобождённую память
повторно, поэтому без этой оптимизации цикл расходовал бы его запас с каждым проходом.

Тот же блок занимает и другой тип, если блок его вмещает, поэтому более узкий тип
использует блок, взятый под более широкий. Новому типу, для которого есть место во
встроенном буфере, блок не нужен: такой объект размещается в буфере, а блок возвращается
аллокатору. Одного совпадения размеров для размещения в буфере недостаточно, поскольку
объект в буфере переносится перемещением. Тип, у которого конструктор перемещения способен
выбросить исключение, размещается в выделенной памяти, даже когда подходит по размеру.

Присваивание значения и метод `emplace` доходят до этой оптимизации по-разному.
Сконструировать объект на месте прежнего можно, только разрушив прежний. Метод `emplace`
разрушает прежний объект первым по своему определению, поэтому сохраняет память для любого
типа. Присваивание значения так поступить не может, поскольку новое значение бывает частью
прежнего вложенного объекта, и разрушение прежнего первым означало бы чтение из
разрушенного. Поэтому сначала, пока прежний объект ещё существует, конструируется временная
копия нового значения. Исключение на этом шаге безопасно, объект типа `scl::any` остаётся
нетронутым. Затем прежний объект разрушается, а временная копия переносится на его место
перемещением. Это перемещение выбросить исключение уже не может: между разрушением и
переносом память не содержит объекта, и восстанавливать в ней нечего. Отсюда следует
условие повторного использования: у вложенного типа есть конструктор перемещения, который не
выбрасывает исключений, и объект этого типа занимает не более 256 байт. Второе условие
ограничивает не хранилище, а размер временной копии: копия объявляется как обычная
переменная нужного типа, поэтому компилятор выравнивает её сам, а 256 байт - та граница, за
которой такая копия обходится дороже нового обращения к аллокатору. Для остальных типов
запрашивается новая память, а прежний объект разрушается после того, как замена
сконструирована.

Значение, пришедшее через представление [`any_view`](any_view.md),
[`any_mutable_view`](any_mutable_view.md) или аргумент [`any_arg`](any_arg.md), принимается
на тех же условиях. Тип этого значения в месте вызова не назван, поэтому временную копию
конструирует операция из описания типа, которое представление несёт с собой.

Блок памяти можно запросить заранее и вернуть аллокатору по требованию:

```cpp
scl::any value;

value.reserve_space_for<three_doubles>();      // одно выделение, объекта пока нет
value.has_space_for<three_doubles>();          // true
value.emplace<three_doubles>(1.0, 2.0, 3.0);   // выделения не происходит

value.emplace<narrower>();                     // блок вмещает, выделения не происходит
value.shrink_to_fit();                         // отдаёт то, что осталось неиспользованным
```

Методы `reserve_space_for<T>()` и `shrink_to_fit()` могут не выполнить никаких действий,
поскольку выражают просьбу, а не обещание. Типу,
который помещается во встроенный буфер, блок не нужен. Объект, уже размещённый в буфере,
блока не занимает, поскольку его размещение следует из типа. Объект, конструктор перемещения
которого может выбросить исключение, перенести нельзя. В каждом из этих случаев вызов не
выполняет никаких действий. Метод `has_space_for<T>()` отвечает, есть ли в уже занятой
памяти место под объект типа `T`, и учитывает оба способа размещения: встроенный буфер и
выделенный блок.

Вложенный объект, который контейнер уже держит, переносится в запрошенный блок, поэтому блок
берётся под большую из двух форм, а не только под резервируемую. После этого метод `emplace`
к аллокатору не обращается. Для присваивания условия строже: значение попадает в блок только
на тех условиях, которые объявляет само присваивание, а значение через представление - только
если блок занят объектом. Поэтому и присваивание значения, и присваивание через представление
могут обратиться к аллокатору. Все три метода работают только во время выполнения, поскольку
блок представляет собой сырые байты, а в константных выражениях в сырых байтах не существует
ни одного объекта.

Блок, запрошенный и ни разу не заполненный, возвращают аллокатору методы `reset()`,
`shrink_to_fit()` и деструктор, а при перемещении и обмене такой блок переходит к
получателю.

### Копирование

У типа `scl::any` нет ни конструктора копирования, ни оператора копирующего присваивания.
Именно поэтому он хранит объект типа, у которого нет конструктора копирования, но и сам
оказывается только перемещаемым: контейнер `std::vector<scl::any>` можно перемещать, но
нельзя копировать, а обобщённый код, требующий `std::copy_constructible`, такой тип
отвергнет.

Копию запрашивает функция `scl::any::try_copy()`. Сама она копии не делает: она возвращает
объект неописанного типа, который принимают конструктор и оператор присваивания контейнера.
Поэтому вызов вне конструирования или присваивания не выполняет никаких действий:

<!-- snippet: example/any/owning/any_owning_example.cpp copying -->
```cpp
static void show_copying()
{
    ::scl::any const text{::std::string{"copy me"}};

    // is_copyable() asks about the stored type, so an empty result of the copy is
    // never ambiguous.
    ::scl::any const copy = ::scl::any::try_copy(text);

    // A move-only type is storable precisely because copying is not a constructor.
    ::scl::any const owned{::std::make_unique<int>(42)};
    ::scl::any const refused = ::scl::any::try_copy(owned);

    ::std::cout
        << "  is_copyable=" << text.is_copyable() << " copy=\""
        << *::scl::any_cast<::std::string>(&copy) << "\"\n";
    ::std::cout
        << "  unique_ptr is_copyable=" << owned.is_copyable()
        << " copy has_value=" << refused.has_value() << '\n'; // 0 0
}
```

Метод `is_copyable()` сообщает о вложенном **типе**, поэтому пустой результат копирования
понимается однозначно. Пустым он может быть только в двух случаях: вложенного объекта не
было вовсе либо у его типа нет конструктора копирования. Исключение, выброшенное
конструктором копирования или аллокатором, не перехватывается и передаётся вызывающей
стороне.

Аллокатор для копии контейнер получает от аллокатора источника через
`select_on_container_copy_construction`. Если копия делается из представления, у которого
своего аллокатора нет, то аллокатор конструируется по умолчанию. Указать аллокатор явно
можно тегом `std::allocator_arg`:

```cpp
scl::any const copy{std::allocator_arg, allocator, scl::any::try_copy(source)};
```

### Перемещение и обмен

<!-- snippet: example/any/owning/any_owning_example.cpp moving -->
```cpp
static void show_moving()
{
    // An allocated object moves by handing over its pointer, an in-place one by
    // relocation - which only a nothrow-movable type ever undergoes.
    ::scl::any source{::std::string{"moved"}};
    ::scl::any const target{::std::move(source)};

    // NOLINTNEXTLINE(bugprone-use-after-move): emptiness after a move is the contract
    ::std::cout << "  after the move, source has_value=" << source.has_value() << '\n'; // 0
    ::std::cout << "  target holds \"" << *::scl::any_cast<::std::string>(&target) << "\"\n";
}
```

Конструктор перемещения, оператор перемещающего присваивания и метод `swap()` объявлены
`noexcept` безусловно. Объект, размещённый в выделенной памяти, переходит вместе с
указателем на него и сам не перемещается. Объект, размещённый внутри объекта типа
`scl::any`, переносится перемещением, но в буфере хранятся только типы, у которых
конструктор перемещения не выбрасывает исключений.

### Запросы идентичности

```cpp
scl::any const value{42};

value.has_value();                              // true
value.type_name();                              // "int"
value.type_key() == scl::type_key_of<int>();    // true
scl::any{}.type_key() == scl::type_key{};       // true: пустой any не хранит типа
```

Метод `type_key()` возвращает значение [`scl::type_key`](../meta/type_key.md), как и
одноимённые методы остальных типов этой группы. Пустой контейнер не хранит никакого типа и
возвращает пустой ключ. Равенство `type_key().name() == type_name()` выполняется всегда.

### Где размещается объект

Способ размещения определяется типом вложенного объекта и ёмкостью встроенного буфера и
выбирается на этапе компиляции:

| Условие | Где размещается вложенный объект |
|---|---|
| `sizeof(T) <= buffer_capacity`, `alignof(T) <= alignof(void *)`, конструктор перемещения не выбрасывает исключений | внутри объекта типа `scl::any` |
| ни одно из условий не выполнено | в памяти, выделенной аллокатором с выравниванием этого типа |
| вычисление на этапе компиляции | всегда в выделенной памяти |

Константа `buffer_capacity` содержит встроенную ёмкость, которой тип располагает на самом
деле. Она не меньше `sizeof(void *)`, поэтому меньшее значение параметра `Capacity`
округляется вверх до этой величины.

Тип с повышенным выравниванием во встроенный буфер не попадает никогда: такой объект
размещается в памяти, полученной с нужным ему выравниванием, каким бы оно ни было. Блок
несёт запас, достаточный для выравнивания объекта внутри себя, поэтому ни одно выравнивание
не отвергается.

Параметра выравнивания у шаблона нет намеренно, поскольку он увеличил бы размер типа для
всех. Выравнивание `alignof(std::max_align_t)` довело бы размер типа `scl::any` до четырёх
указателей, а выравнивание по строке кэша - до шестнадцати.

Более широкий буфер может быть задан вторым параметром шаблона:

```cpp
using roomy_any = scl::basic_any<std::allocator<std::byte>, 48>;   // 56 байт на x86-64
```

Каждая пара параметров шаблона образует отдельный тип, и между такими типами значение не
переносится: ни перемещения, ни метода `swap()`, ни присваивания одной специализации в
другую нет. Иначе вложенный объект пришлось бы переносить между буферами разной ширины и
между разными аллокаторами, а это вызов конструктора перемещения вложенного типа, после
которого перемещение самого объекта типа `scl::any` перестало бы быть `noexcept`.

Перенести значение между специализациями можно с помощью метода `try_copy()`, который
принимает представление:

```cpp
roomy_any source{std::string{"Hello Any!"}};

scl::any taken = scl::any::try_copy(scl::any_view{source});   // копия строки
```

Копию создаёт конструктор копирования вложенного типа, поэтому значение типа без такого
конструктора перенести нельзя, и целевой контейнер останется пустым. Сам объект типа
`scl::any` можно разместить внутри другого, указав его тип явно:
`scl::any{std::in_place_type<roomy_any>, ...}`.

### Аллокатор следует за объектом

Оператор перемещающего присваивания и метод `swap()` переносят аллокатор вместе с вложенным
объектом. Свойства аллокатора `propagate_on_container_move_assignment` и
`propagate_on_container_swap` при этом не учитываются:

```cpp
pmr_any source{std::allocator_arg, pmr_allocator{&first}};
source.emplace<std::string>(64U, 'x');
pmr_any target{std::allocator_arg, pmr_allocator{&second}};

target = std::move(source);
target.get_allocator().resource() == &first;   // true: аллокатор перешёл вместе с объектом
```

Причина в том, что память, выделенную одним аллокатором, освободить может только он же.
Правило, принятое для контейнеров стандартной библиотеки, то есть перенос объекта в
аллокатор приёмника, здесь неприменимо: такой перенос потребовал бы конструктора перемещения
от каждого вложенного типа, то есть ровно того требования, без которого тип `scl::any` и
задуман.

Копирования это правило не касается. Оно конструирует новый вложенный объект, поэтому
запрашивает аллокатор для копии обычным способом, через свойство
`select_on_container_copy_construction`.

### Вычисление на этапе компиляции

В константных выражениях доступны все операции, кроме размещения вложенного объекта внутри
объекта типа `scl::any`:

<!-- snippet: example/any/owning/any_owning_example.cpp constant_evaluation -->
```cpp
static constexpr ::std::size_t stored_length()
{
    ::scl::any value{::std::string{"Hello Any!"}};
    ::std::size_t const length = ::scl::any_cast<::std::string>(&value)->size();

    value.reset();
    return length;
}
```

Контейнер, объявленный внутри `constexpr`-функции, доступен там в конструировании, чтении,
замене и очистке. Три операции с блоком — `reserve_space_for`, `shrink_to_fit` и
`has_space_for` — выполняются только во время работы программы. `constexpr`-функция,
которая вызывает любую из них, компилируется и работает при обычном вызове, но константным
выражением быть не может: компилятор отвергает не её определение, а `static_assert` над ней.
Переменная `constexpr scl::any` на
уровне пространства имён может быть только пустой: память, выделенную при вычислении на
этапе компиляции, необходимо освободить до конца этого вычисления, а встроенный буфер там
недоступен, поскольку в сырых байтах на этапе компиляции объект не существует. Стандарт
C++26 это ограничение не снимает.

Представление [`any_view`](any_view.md) и аргумент [`any_arg`](any_arg.md), построенные над
объектом типа `scl::any`, читаются в константных выражениях наравне с самим контейнером, и
[якорь](any_anchor.md) им для этого не нужен: контейнер размещает вложенный объект так, что
функция `scl::any_cast` доходит до него без преобразования указателя на `void`, которое до
стандарта C++26 в константных выражениях запрещено. Над значением, размещённым не в
контейнере, а рядом с представлением, якорь как раз и нужен, и об этом сказано на его
собственной странице.

Копия из представления в константных выражениях делается тем же методом `try_copy()`:

```cpp
constexpr int taken()
{
    scl::any const source{42};
    scl::any_view const view{source};
    scl::any const copy = scl::any::try_copy(view);

    return *scl::any_cast<int>(&copy);
}

static_assert(taken() == 42);
```

У этой копии есть дополнительное условие: аллокатор у обеих сторон должен быть один и тот
же и сам должен работать в константных выражениях. Причина в том, что копию создаёт
операция из описания типа, а такое описание контейнер формирует под свой аллокатор. Описание,
сформированное под другой аллокатор, содержит другую операцию, и одно другому не подходит.
Чтение через представление этого условия не имеет и работает всегда.

### Чтение через представления

Представления [`any_view`](any_view.md), [`any_mutable_view`](any_mutable_view.md),
аргумент [`any_arg`](any_arg.md) и цепочка [`any_switch`](any_switch.md) принимают объект
типа `scl::any` и читают вложенный объект, а не сам контейнер:

```cpp
scl::any value{42};

void report(scl::any_view view);   // view.type_name() возвращает "int", а не "scl::any"
void bump(scl::any_arg arg);       // any_cast<int>(&arg) пишет во вложенный объект
```

Объект типа `std::any` представление считает обычным значением и до вложенного в него
объекта не доходит. Метод `type_name()` такого представления возвращает `"std::any"`, а
приведение возвращает сам объект типа `std::any`. Прочитать то, что он хранит, позволяет
заголовок [`<scl/utility/any/std_any.h>`](std_any.md). Этим два контейнера и различаются:
вложенный объект контейнера `scl::any` представление отдаёт, а вложенный объект контейнера
`std::any` - нет.

Представления ссылаются на вложенный объект внутри контейнера. Поэтому очистка, повторное
присваивание значения или перемещение объекта типа `scl::any` делают такое представление
недействительным, так же как значение `std::string_view` становится недействительным после
изменения строки.

### Копия объекта, на который ссылается представление

Представление [`any_view`](any_view.md), представление
[`any_mutable_view`](any_mutable_view.md) и аргумент [`any_arg`](any_arg.md) не владеют
объектом, на который ссылаются. Контейнер получает копию этого объекта и становится её
владельцем. Копию запрашивает тот же метод `try_copy()`, что и при копировании из другого
контейнера, - его описание дано выше, в разделе «Копирование»:

```cpp
std::string text{"Hello Any!"};
scl::any_view const view{text};

scl::any value = scl::any::try_copy(view);        // хранит собственную std::string
value = scl::any::try_copy(scl::any_arg{text});   // то же самое присваиванием
```

Тип объекта, на который ссылается представление, в месте вызова не назван, поэтому копию
создаёт операция из описания типа, которое представление несёт с собой. Есть ли в этом
описании такая операция, компилятор проверить не может, и результат становится известен
только при выполнении программы. Отсюда три случая, в которых контейнер остаётся пустым:
представление ни на что не ссылается, у типа объекта нет конструктора копирования, либо
объект является массивом. Массив константных символов, то есть тип строкового литерала,
составляет то же исключение, что и при конструировании из значения, и копируется как
указатель на свой первый элемент:

```cpp
scl::any taken = scl::any::try_copy(scl::any_arg{"abc"});   // хранит char const *
```

Поэтому результат следует проверять:

```cpp
scl::any copy = scl::any::try_copy(view);
if (!copy.has_value())
{
    // объект, на который ссылается представление, скопировать не удалось
}
```

Аллокатора у представления нет, поэтому при конструировании аллокатор копии конструируется
по умолчанию, а при присваивании копия размещается в памяти, которую даёт аллокатор
контейнера-приёмника.

Контейнер `std::any` такой копии не делает: его собственный конструктор принимает
представление в виде ссылки как обычное значение и сохраняет само представление. Контейнер
`scl::any` тоже может сохранить представление, если указать его тип явно:

```cpp
scl::any stored{std::in_place_type<scl::any_view>, view};   // хранит представление
```

### Идентичность через границы модулей

Приведение сравнивает значения [`scl::type_key`](../meta/type_key.md) и подчиняется тем же
двум ограничениям, что и представление. Тип, объявленный внутри блока, лежит вне контракта
ключа. Само значение ключа не должно пережить модуль, который его создал.
