# Any

`scl::any` - контейнер, который хранит одно значение любого типа: создаёт его, держит и
разрушает вместе с собой. Тип хранимого объекта не входит в тип `scl::any`, поэтому одна
и та же переменная в разное время хранит объекты разных типов, а функция принимает и
возвращает такое значение, не зная его типа заранее.

- Заголовок: `#include <scl/utility/any/any.h>`

## Обзор

Стандартный `std::any` решает ту же задачу, но опирается на две вещи, доступные не в
любой сборке.

Во-первых, `std::any` определяет тип хранимого объекта через `typeid`, то есть требует
включённой информации о типах времени выполнения (RTTI). Если проект собирается с ключом
`-fno-rtti`, воспользоваться `std::any` не получится.

Во-вторых, ни одна операция `std::any` не выполняется в константном выражении. Значение,
тип которого известен уже при компиляции, приходится обслуживать другими средствами.

`scl::any` снимает оба ограничения. Типы он различает не через `typeid`, а через
[`scl::type_key`](../meta/type_key.md) - объект, который библиотека заводит по одному на
каждый тип и сравнивает по адресу. Поэтому заголовок компилируется с отключённым RTTI. А
конструирование, `emplace`, `any_cast`, `reset` и разрушение выполняются в том числе на
этапе компиляции.

`sizeof(scl::any)` равен двум указателям. Столько же `std::any` занимает в libstdc++; в
libc++ он занимает вдвое больше, а в реализации MSVC - вчетверо. То есть переход с
`std::any` на `scl::any` не увеличит расход памяти ни в одной из этих стандартных
библиотек.

Небольшой объект `scl::any` размещает прямо в себе и не обращается к аллокатору. Так
хранится объект, который помещается во встроенный буфер, не требует выравнивания строже
указателя и перемещается без исключений. Остальные объекты `scl::any` размещает в
памяти, которую берёт у аллокатора. Выбор между двумя способами делается для каждого
типа при компиляции и не стоит ни байта: встроенный буфер занимает то же место, что и
указатель на выделенный объект.

От типа хранимого объекта требуются два свойства: объект можно разрушить без исключений и
объект можно построить из переданных аргументов. Больше никаких требований нет.

В частности, `scl::any` хранит объект, который нельзя переместить: такой объект
размещается в выделенной памяти, а при перемещении `scl::any` указатель на объект
переходит к новому контейнеру, сам объект остаётся на месте. Хранит он и объект, который нельзя
скопировать, - потому что копирование в этом типе выполняет не конструктор, а
отдельный метод. Это единственное заметное отличие от `std::any`: сам `scl::any`
копировать нельзя, его можно только перемещать, а копию хранимого объекта запрашивают
вызовом `try_copy()`.

Аллокатор и размер встроенного буфера задаются параметрами шаблона
`scl::basic_any<Allocator, Capacity>`. Имя `scl::any` обозначает `basic_any<>` - то есть
`std::allocator<std::byte>` и буфер размером с указатель.

## Возможности

- Хранит объект любого типа, который можно разрушить, и не использует RTTI.
- Занимает два указателя - столько же, сколько `std::any` в libstdc++.
- Выполняет полный жизненный цикл объекта на этапе компиляции, начиная с C++20.
- Размещает небольшой объект в себе, не обращаясь к аллокатору.
- Принимает аллокатор параметром шаблона, в том числе аллокатор с состоянием, например
  `std::pmr::polymorphic_allocator`.
- Перемещается, но не копируется; копию хранимого объекта выдаёт `try_copy()`, а
  `is_copyable()` заранее сообщает, возможна ли она.
- Объявляет перемещение, `swap()` и `reset()` как `noexcept`.
- Отдаёт указатель на хранимый объект через `any_cast<T>(any *)`; при несовпадении типа
  возвращается `nullptr`, исключение не выбрасывается. Через неконстантный `scl::any`
  такой указатель разрешает запись.
- Отдаёт значение или ссылку через `any_cast<T>(any &&)`; при несовпадении типа
  выбрасывает `scl::bad_any_cast`.
- Читается через [`any_view`](any_view.md), [`any_arg`](any_arg.md) и
  [`any_switch`](any_switch.md), причём они читают хранимый объект, а не сам
  `scl::any`.
- Построенный из представления или аргумента, хранит копию объекта, на который тот
  ссылается, а не сам источник.

## Справочник по API

### Конструирование

```cpp
scl::any empty{};                                 // ничего не хранит
scl::any number{42};                              // размещён в самом any
scl::any text{std::string{"Hello Any!"}};         // размещён в выделенной памяти
scl::any built{std::in_place_type<std::string>, 3U, 'x'};  // "xxx", без временного объекта
scl::any made = scl::make_any<std::string>(3U, 'x');       // то же самое выражением
```

Конструктор, принимающий значение, применяет к типу аргумента `decay` - так же
поступает `std::any`. Поэтому строковый литерал хранится как `char const *`, а имя
функции - как указатель на функцию.

Форма с `std::in_place_type` строит объект сразу в хранилище из переданных аргументов и
не создаёт временный объект. Она же позволяет хранить тип, который нельзя переместить.

Аллокатор передаётся первым аргументом вместе с тегом `std::allocator_arg`:

<!-- snippet: example/any/owning/any_owning_example.cpp allocator -->
```cpp
static void show_allocator()
{
    ::std::pmr::monotonic_buffer_resource resource;
    using pmr_any = ::scl::basic_any<::std::pmr::polymorphic_allocator<::std::byte>>;

    pmr_any value{::std::allocator_arg, ::std::pmr::polymorphic_allocator<::std::byte>{&resource}};
    value.emplace<::std::string>(64U, 'x');

    ::std::cout
        << "  allocated from the given resource? " << (value.get_allocator().resource() == &resource) << '\n'; // 1

    // The allocator travels with the object: what one allocator acquired, only
    // that allocator may release.
    pmr_any const taken{::std::move(value)};
    ::std::cout << "  and travels with it? " << (taken.get_allocator().resource() == &resource) << '\n'; // 1
}
```

### Чтение и запись

```cpp
scl::any value{42};

if (auto * number = scl::any_cast<int>(&value))   // int *: запись доходит до объекта
    *number = 7;

scl::any const frozen{42};
scl::any_cast<int>(&frozen);                      // int const *: только чтение
scl::any_cast<double>(&value);                    // nullptr: тип не совпал
scl::any_cast<int>(value);                        // 7, копия значения
scl::any_cast<double>(value);                     // выбрасывает scl::bad_any_cast
```

Форма с указателем возвращает `nullptr`, когда запрошенный тип не совпадает с типом
хранимого объекта, и не выбрасывает исключений. Форма со ссылкой в этом случае
выбрасывает `scl::bad_any_cast`; она объявлена только там, где
[`SCL_HAS_EXCEPTIONS`](../preprocessor/exceptions.md) равен `1`.

Права доступа наследуются от того, как обращаются к самому `scl::any`. Константный
`scl::any` отдаёт указатель на константу, неконстантный разрешает запись. Именно этим
контейнер отличается от [`any_view`](any_view.md), который записи не даёт никогда.

### Замена и очистка

```cpp
scl::any value{42};

value = std::string{"Hello Any!"};      // разрушает int, сохраняет строку
value.emplace<std::string>(3U, 'x');    // строит строку из аргументов на месте
value.reset();                          // разрушает объект, оставляет any пустым
```

Оператор присваивания хранимого типа при этом не вызывается никогда, как и у
`std::any`: прежний объект разрушается, а новый строится заново.

Два способа замены - присваивание значения и `emplace` - различаются порядком действий, и
от этого зависит их поведение при исключении.

Присваивание значения сначала получает новое значение и только потом разрушает прежний
объект. Поэтому конструктор, выбросивший исключение, оставляет прежний объект нетронутым.
`emplace` разрушает прежний объект первым, поэтому конструктор, выбросивший исключение,
оставляет `scl::any` пустым. Это та же гарантия, что даёт `std::any::emplace`.

От порядка зависит и то, каким может быть аргумент. `emplace` читает свои аргументы уже
после того, как прежний объект разрушен. Если аргумент указывает внутрь прежнего объекта
- на сам объект, на его член или на то, чем он распоряжается, - `emplace` прочитает
разрушенное значение. Присваивание значения читает такой аргумент, пока прежний объект
ещё цел:

```cpp
scl::any value{owner{std::make_unique<payload>()}};

value = *scl::any_cast<owner>(&value)->held;   // источник живёт внутри хранимого объекта
```

Присваивание объекту его же собственного значения не делает ничего - ни значением, ни
через представление:

```cpp
scl::any value{std::make_unique<int>(42)};

value = scl::any_view{value};    // ничего не происходит: unique_ptr остаётся на месте
```

Именно это позволяет сохранить значение типа, который нельзя копировать: копия
невозможна, а замена оставила бы `scl::any` пустым. Если же представление или значение
называет **член** хранимого объекта, то это обычная замена.

Указатели внутрь хранимого объекта после замены и после `reset()` использовать нельзя:
объект, на который они указывали, разрушен.

### Повторное использование памяти

Замена сохраняет уже выделенную память, если новый объект тоже размещается в выделенной
памяти и блок его по-прежнему вмещает. Тогда аллокатор не вызывается ни для освобождения, ни
для нового выделения: новый объект строится там, где стоял прежний.

```cpp
pmr_any value{std::allocator_arg, pmr_allocator{&resource}};
value = three_doubles{1.0, 2.0, 3.0};                        // одно выделение памяти

for (int round = 0; round < 16; ++round)
    value = three_doubles{double(round), 0.0, 0.0};           // выделений больше нет
```

Больше всего это значит там, где освобождение памяти ничего не возвращает.
`std::pmr::monotonic_buffer_resource` не выдаёт освобождённую память повторно, поэтому
без такой оптимизации цикл расходовал бы её запас с каждым проходом.

Ту же память занимает и другой тип, если блок его вмещает, поэтому более узкий тип
переиспользует блок, взятый под более широкий. Исключение одно: если
новому типу место во встроенном буфере, он размещается там, а выделенная память
возвращается аллокатору. Совпадения размеров для буфера мало - объект в буфере
переносится перемещением, поэтому тип, перемещение которого способно выбросить
исключение, размещается в выделенной памяти, даже когда подходит по размеру.

Присваивание значения и `emplace` доходят до этой оптимизации по-разному, и вот почему.
Построить объект на месте прежнего можно, только разрушив прежний. `emplace` разрушает
первым по своему определению, поэтому сохраняет память для любого типа. Присваивание
значения так не может: новое значение бывает частью прежнего объекта, и разрушить прежний
первым значило бы читать из уничтоженного. Поэтому сначала, пока прежний объект цел,
строится временная копия нового значения - выбросить исключение на этом шаге безопасно,
`any` остаётся нетронутым, - и лишь затем прежний объект разрушается, а копия переносится
на его место перемещением. Вот это перемещение выбросить уже не может: между разрушением и
переносом память не содержит объекта, и вернуть в неё нечего. Отсюда и условие
переиспользования: тип перемещается без исключений и не шире 256 байт, потому что копия
живёт на стеке. Для остальных запрашивается новая память, а прежний объект разрушается
после того, как замена построена.

Значение, пришедшее через [`any_view`](any_view.md) или [`any_arg`](any_arg.md),
принимается на тех же условиях. Тип такого значения здесь не назван, поэтому временную
копию строит операция, которую источник несёт в своём описании типа.

### Копирование

У `scl::any` нет ни копирующего конструктора, ни копирующего присваивания. Именно
поэтому он хранит некопируемый объект - но сам оказывается только перемещаемым:
`std::vector<scl::any>` можно перемещать, но не копировать, а обобщённый код,
требующий `std::copy_constructible`, такой тип отвергнет.

Копия запрашивается явно:

<!-- snippet: example/any/owning/any_owning_example.cpp copying -->
```cpp
static void show_copying()
{
    ::scl::any const text{::std::string{"copy me"}};

    // is_copyable() asks about the stored type, so an empty result of try_copy() is
    // never ambiguous.
    ::scl::any const copy = text.try_copy();

    // A move-only type is storable precisely because copying is not a constructor.
    ::scl::any const owned{::std::make_unique<int>(42)};
    ::scl::any const refused = owned.try_copy();

    ::std::cout
        << "  is_copyable=" << text.is_copyable() << " copy=\""
        << *::scl::any_cast<::std::string>(&copy) << "\"\n";
    ::std::cout
        << "  unique_ptr is_copyable=" << owned.is_copyable()
        << " copy has_value=" << refused.has_value() << '\n'; // 0 0
}
```

`is_copyable()` отвечает о хранимом **типе**, поэтому пустой результат `try_copy()`
понимается однозначно. Пустым он бывает в двух случаях: копируемого объекта не было
вовсе или его тип не поддерживает копирование. Исключение, выброшенное копирующим
конструктором или аллокатором, `try_copy()` не перехватывает и передаёт вызывающей
стороне.

### Перемещение и обмен

<!-- snippet: example/any/owning/any_owning_example.cpp moving -->
```cpp
static void show_moving()
{
    // An allocated object moves by handing over its pointer, an in-place one by
    // relocation - which only a nothrow-movable type ever undergoes.
    ::scl::any source{::std::string{"moved"}};
    ::scl::any const target{::std::move(source)};

    // NOLINTNEXTLINE(bugprone-use-after-move): emptiness after a move is the contract
    ::std::cout << "  after the move, source has_value=" << source.has_value() << '\n'; // 0
    ::std::cout << "  target holds \"" << *::scl::any_cast<::std::string>(&target) << "\"\n";
}
```

Перемещающий конструктор, перемещающее присваивание и `swap()` объявлены `noexcept`
безусловно. Выделенный объект переходит вместе с указателем на него и не перемещается
сам. Объект, размещённый внутри `scl::any`, переносится перемещением, но там хранятся
только типы, перемещение которых не выбрасывает исключений.

### Запросы идентичности

```cpp
scl::any const value{42};

value.has_value();                              // true
value.type_name();                              // "int"
value.type_key() == scl::type_key_of<int>();    // true
scl::any{}.type_key() == scl::type_key{};       // true: пустой any не хранит типа
```

`type_key()` возвращает [`scl::type_key`](../meta/type_key.md) по значению, как и все
типы этой группы. Пустой контейнер не хранит никакого типа и возвращает пустой ключ.
Равенство `type_key().name() == type_name()` выполняется всегда.

### Где размещается объект

Способ хранения определяется типом объекта и ёмкостью буфера, и выбирается при
компиляции:

| Условие | Где размещается объект |
|---|---|
| `sizeof(T) <= max(Capacity, sizeof(void *))`, `alignof(T) <= alignof(void *)`, перемещение без исключений | внутри самого `scl::any` |
| ни одно из условий не выполнено | в памяти, выделенной аллокатором с выравниванием этого типа |
| вычисление на этапе компиляции | всегда в выделенной памяти |

Тип с повышенным выравниванием во встроенный буфер не попадает никогда: он размещается в
памяти, полученной с нужным ему выравниванием, каким бы оно ни было. Блок несёт запас,
достаточный чтобы выровнять объект внутри себя, поэтому ни одно выравнивание не отвергается.

Параметра выравнивания у шаблона нет намеренно: он увеличил бы размер типа для всех.
Выравнивание `alignof(std::max_align_t)` довело бы `scl::any` до четырёх указателей, а
выравнивание по строке кэша - до шестнадцати.

Более широкий буфер задаётся вторым параметром шаблона:

```cpp
using roomy_any = scl::basic_any<std::allocator<std::byte>, 48>;   // 56 байт
```

Каждая пара параметров даёт отдельный тип, и между собой такие типы не переносятся:
ни перемещения, ни `swap()`, ни присваивания одной специализации в другую нет. Иначе
объект пришлось бы переносить между буферами разной ширины и между разными аллокаторами,
а это вызов конструктора перемещения хранимого типа - и перемещение самого `scl::any`
перестало бы быть `noexcept`.

Значение переносится через представление, копией:

```cpp
roomy_any source{std::string{"Hello Any!"}};

scl::any taken{scl::any_view{source}};   // копия строки, а не сам roomy_any
```

Копию делает копирующий конструктор хранимого типа, поэтому некопируемое значение так не
перенести - целевой контейнер останется пустым. Сам `scl::any` кладётся внутрь другого
только явным написанием: `scl::any{std::in_place_type<roomy_any>, ...}`.

### Аллокатор следует за объектом

Перемещающее присваивание и `swap()` переносят аллокатор вместе с объектом. Свойства
`propagate_on_container_move_assignment` и `propagate_on_container_swap` при этом не
учитываются:

```cpp
pmr_any source{std::allocator_arg, pmr_allocator{&first}};
source.emplace<std::string>(64U, 'x');
pmr_any target{std::allocator_arg, pmr_allocator{&second}};

target = std::move(source);
target.get_allocator().resource() == &first;   // true: аллокатор перешёл вместе с объектом
```

Причина в том, что память, выделенную одним аллокатором, освободить может только он же.
Правило, принятое для контейнеров, - перенести объект в аллокатор приёмника - здесь
неприменимо: перенос потребовал бы перемещающего конструктора от каждого хранимого
типа, то есть ровно того требования, без которого этот тип и задуман.

`try_copy()` этого правила не касается. Он строит новый объект, поэтому запрашивает
аллокатор для копии обычным способом - через
`select_on_container_copy_construction`.

### Вычисление на этапе компиляции

На этапе компиляции доступно всё, кроме размещения объекта внутри самого `scl::any`:

<!-- snippet: example/any/owning/any_owning_example.cpp constant_evaluation -->
```cpp
static constexpr ::std::size_t stored_length()
{
    ::scl::any value{::std::string{"Hello Any!"}};
    ::std::size_t const length = ::scl::any_cast<::std::string>(&value)->size();

    value.reset();
    return length;
}
```

Внутри `constexpr`-функции ограничений нет. А вот переменная `constexpr scl::any` на
уровне пространства имён может быть только пустой, и вот почему. Память, выделенную при
вычислении на этапе компиляции, обязательно нужно освободить до конца этого вычисления,
а встроенный буфер там недоступен: в сырых байтах на этапе компиляции объект не
существует. C++26 это ограничение не снимает.

Представления и аргументы над `scl::any` читаются на этапе компиляции наравне с самим
контейнером, и якорь им для этого не нужен: значение размещено внутри служебного объекта,
который `scl::any` создаёт в любом случае, и `any_cast` получает доступ к значению,
преобразуя указатель на базовый тип в указатель на сам объект. Там же выполняется и
обратное - копирование значения из представления:

```cpp
constexpr int taken()
{
    scl::any const source{42};
    scl::any_view const view{source};
    scl::any const copy{view};

    return *scl::any_cast<int>(&copy);
}

static_assert(taken() == 42);
```

Копирование значения на этапе компиляции требует, чтобы у обеих сторон был один и тот же
аллокатор и чтобы сам этот аллокатор работал во время константных вычислений. Копия
делается через собственное описание объекта, которое контейнер создал, а такое описание
называет тот аллокатор, для которого оно создано; описание, созданное для другого
аллокатора, называет другой, и эти два не встречаются. Чтение через представление
работает в любом случае.

### Чтение через представления

[`any_view`](any_view.md), [`any_arg`](any_arg.md) и [`any_switch`](any_switch.md)
принимают `scl::any` и читают хранимый объект, а не сам `scl::any`:

```cpp
scl::any value{42};

void report(scl::any_view view);   // view.type_name() возвращает "int", а не "scl::any"
void bump(scl::any_arg arg);       // any_cast<int>(&arg) пишет в хранимый объект
```

С `std::any` внутри представления получается иначе: он не разворачивается. Метод
`type_name()` возвращает `"std::any"`, приведение возвращает сам этот объект, а то, что он
хранит, читают через [`<scl/utility/any/std_any.h>`](std_any.md). Это единственное, чем два
контейнера расходятся: `scl::any` - объект, на который ссылается представление, а
`std::any` - обычное значение.

Представление ссылается на объект внутри `scl::any`. Поэтому очистка, повторное
присваивание значения или перемещение `scl::any` делают представление недействительным -
так же,
как `std::string_view` становится недействительным после изменения строки.

### Как значение попадает в any из представления

Представление и аргумент работают и в обратную сторону. `scl::any`, построенный или
присвоенный из [`any_view`](any_view.md) либо [`any_arg`](any_arg.md), хранит копию
объекта, на который тот ссылается, а не сам источник:

```cpp
std::string text{"Hello Any!"};
scl::any_view const view{text};

scl::any value = view;                 // хранит собственную std::string
value = scl::any_arg{text};            // то же самое через аргумент
scl::any taken = scl::any_arg{"abc"};  // char const *: массив распадается в указатель
```

`std::any` так поступить не может: его собственный конструктор принимает представление
как обычное значение и сохраняет само представление.

Тип объекта, на который ссылается источник, здесь не назван, поэтому копия делается
через описание типа, которое источник несёт с собой. Неудача поэтому обнаруживается во
время выполнения: если у объекта нет копирующего конструктора, `scl::any` останется пустым.
На этапе компиляции такое копирование недоступно, потому что объект источника там
недостижим.

Сохранить само представление тоже можно, но об этом нужно сказать явно:

```cpp
scl::any stored{std::in_place_type<scl::any_view>, view};   // хранит представление
```

### Идентичность через границы модулей

Приведение сравнивает значения [`scl::type_key`](../meta/type_key.md) и подчиняется тем
же двум ограничениям, что и представление. Тип, объявленный внутри блока, лежит вне
контракта ключа. Сам ключ не должен пережить модуль, который его создал.
