# Any view

`scl::any_view` описывает объект, который может ссылаться на постоянное значение любого
типа. Тип этого значения известен только во время выполнения. Представление значение
только читает: оно его не создаёт, не копирует и не разрушает, а хранит его адрес вместе
с описанием типа.

- Заголовок: `#include <scl/utility/any/any_view.h>`

## Обзор

Отношение `scl::any_view` к `std::any` такое же, какое `std::string_view` имеет
к `std::string`. Функция, которой нужно прочитать значение неизвестного типа, принимает
представление и не заставляет вызывающую сторону складывать значение в контейнер.
Копирование и выделение памяти при этом не выполняются.

Представление занимает два указателя и копируется тривиально.

Сослаться оно может на объект двумя способами. В первом случае представление ссылается
на типизированный объект напрямую: тип известен уже при компиляции, его задаёт
[`scl::type_key`](../meta/type_key.md), поэтому RTTI не требуется, а `type_name()`,
`type_key()`, `has_value()` и само построение представления вычисляются на этапе
компиляции. Во втором случае представление ссылается на `std::any`, и каждое приведение
передаётся стандартному `std::any_cast`. Поскольку `std::any` требует RTTI, при сборке с
`-fno-rtti` соответствующий конструктор из библиотеки исчезает.

Здесь есть тонкость. Некоторые стандартные библиотеки объявляют `std::any` даже при
отключённом RTTI. Такой объект тогда свяжется с обычным конструктором представления, то
есть будет прочитан как рядовой типизированный объект. Метод `type_name()` по-прежнему
ответит `"std::any"`, но добраться до объекта внутри него `any_cast` уже не сможет.

Читать через представление можно, писать нельзя. Функция `scl::any_cast` возвращает либо
копию значения, либо константную ссылку на него. Запрос неконстантной ссылки или
ссылки на временный объект не компилируется, потому что представление доступа на запись
не даёт.

Представление не хранит значение у себя и не продлевает его жизнь. Оно действительно ровно до
тех пор, пока жив объект, на который оно ссылается, - та же оговорка, что и у
`std::string_view`.

## Возможности

- Ссылается на объект, ничего не копируя, и не даёт доступа на запись.
- Занимает два указателя и копируется тривиально.
- Ссылается на типизированный объект любого типа и не использует RTTI.
- Ссылается на `std::any` и передаёт приведение стандартному `std::any_cast`; такой
  конструктор доступен только в сборках с RTTI.
- Отвечает на запросы `type_name()`, `type_key()` и `has_value()` в том числе на этапе
  компиляции, начиная с C++20.
- Отдаёт указатель через `any_cast<T>(view *)`; при несовпадении типа возвращается
  `nullptr`, исключение не выбрасывается.
- Отдаёт значение или константную ссылку через `any_cast<T>(view &)`; при несовпадении
  типа выбрасывает `scl::bad_any_cast`.
- Преобразуется из `std::any` неявно, поэтому один и тот же `scl::any_cast` читает и
  представление, и `std::any`.

## Справочник по API

### Построение

```cpp
std::string text{"Hello Any!"};

scl::any_view empty{};      // не ссылается ни на какой объект
scl::any_view raw{text};    // ссылается на объект напрямую
scl::any_view alias = raw;  // копируется тривиально
```

Представление принимает только lvalue, то есть именованный объект. Привязка к временному
объекту отвергается компилятором: такое представление стало бы недействительным сразу
после окончания выражения.

В сборке с RTTI `std::any` преобразуется в представление неявно:

```cpp
std::any boxed{text};
scl::any_view over_any{boxed};   // ссылается на std::any
```

Временный `std::any` представление тоже не принимает, поэтому оно не переживёт объект, на
который ссылается.

### Наблюдение

```cpp
std::string text{"Hello Any!"};
scl::any_view raw{text};

raw.has_value();   // true
raw.type_name();   // имя типа std::string; точное написание даёт компилятор,
                   // например "std::basic_string<char>"
raw.type_key();    // scl::type_key const *, обозначающий std::string
```

`has_value()` отвечает `false` в двух случаях: представление пустое или оно ссылается на
пустой `std::any`.

`type_name()` возвращает имя типа, известное при компиляции. Когда представление
ссылается на объект напрямую, это имя самого типа объекта. Когда оно ссылается на
`std::any`, это имя `std::any`, а не имя типа, лежащего внутри.

`type_key()` возвращает указатель, а не ссылку, потому что
[`scl::type_key`](../meta/type_key.md) не имеет пустого значения, а пустое представление
не обозначает никакого типа - в этом случае метод возвращает `nullptr`. Ненулевой
результат совпадает с объектом, который возвращает `scl::type_key_of<T>()`, поэтому
сравнение с ним стоит одного сравнения указателей. Равенство
`type_key()->name() == type_name()` выполняется всегда:

```cpp
raw.type_key() == &scl::type_key_of<std::string>();   // true
scl::any_view{}.type_key();                           // nullptr
```

Чтобы узнать тип объекта внутри `std::any`, вызывайте `any_cast<T>` с самим этим типом
`T`. Вызов `any_cast<std::any>` спрашивает, лежит ли внутри ещё один `std::any`, и обычно
возвращает `nullptr`.

### Приведение

Форма с указателем возвращает константный указатель, когда запрошенный тип совпадает с
типом объекта, и `nullptr` в противном случае. Исключений она не выбрасывает:

```cpp
if (auto const * s = scl::any_cast<std::string>(&raw))
    use(*s);   // без копирования
```

Форма со ссылкой возвращает объект по значению или по константной ссылке и выбрасывает
`scl::bad_any_cast`, если тип не совпал. Результат-ссылка связывается с объектом без
копирования:

```cpp
std::string copy = scl::any_cast<std::string>(raw);                 // копия значения
std::string const & ref = scl::any_cast<std::string const &>(raw);  // без копирования
// scl::any_cast<std::string &>(raw);   // не компилируется: представление не пишет
```

Форма со ссылкой объявлена только там, где
[`SCL_HAS_EXCEPTIONS`](../preprocessor/exceptions.md) равен `1`. Если исключения
отключены, остаётся форма с указателем, и о несовпадении типа она уже сообщает.

Аргумент типа `std::any` преобразуется в представление неявно, поэтому один и тот же
вызов `scl::any_cast` читает и представление, и `std::any` напрямую:

```cpp
std::any boxed{text};
scl::any_cast<std::string>(boxed);   // через неявное преобразование в any_view
```

Тип `scl::bad_any_cast` наследуется от `std::bad_cast` в любой сборке и никогда от
`std::bad_any_cast`. Поэтому обработчик `catch (std::bad_cast const &)` перехватывает его
независимо от настроек сборки, а сам тип не зависит от RTTI.

### Квалификаторы const и volatile

Представление запоминает квалификаторы объекта, к которому его привязали. Приведение
обязано запросить все эти квалификаторы: добавить квалификатор можно, отбросить нельзя.
Квалификатор `const` добавляет само чтение, поэтому на практике запрашивать приходится
только `volatile`:

```cpp
int volatile sensor = 0;
scl::any_view const view{sensor};

scl::any_cast<int>(&view);                 // nullptr: запрос отбросил бы volatile
scl::any_cast<int volatile>(&view);        // int const volatile *
scl::any_cast<int const volatile &>(view); // читает volatile-объект
```

Обратное направление разрешено всегда: запрос с `volatile` проходит и по объекту без
квалификаторов.

То же правило действует и для самого представления. Если переменная объявлена как
`any_view volatile`, этот квалификатор тоже нужно запросить, независимо от квалификаторов
объекта:

```cpp
int number = 0;
scl::any_view volatile view{number};

scl::any_cast<int>(&view);          // nullptr: само представление volatile
scl::any_cast<int volatile>(&view); // читает нормально
```

### Вычисление на этапе компиляции

Построение представления и запросы `type_name()`, `type_key()` и `has_value()`
выполняются на этапе компиляции, начиная с C++20. А вот `any_cast` на этом уровне
выполняется только во время работы программы, ровно как и `std::any_cast`.

Ограничение вызвано способом привязки, а не стиранием типа как таковым. Представление
ссылается на объект любого типа, поэтому запомнить его адрес оно может только как
`void const *`. Восстановление типизированного указателя из `void const *` становится
константным выражением лишь на компиляторах, которые реализовали P2738 (C++26).

Другой способ - стереть тип до общего базового класса - вычислим и на C++20, но для него
рядом с объектом должен существовать экземпляр такого класса, и кто-то обязан
поддерживать его существование всё время жизни описания типа. Для параметра метода это
делает [`any_arg`](any_arg.md#вычисление-на-этапе-компиляции): вызывающая сторона создаёт
такой экземпляр на каждую привязку, а вызов заведомо переживает свои аргументы.
Представление же можно хранить сколько угодно долго, и предоставить такой экземпляр
некому. Поэтому для сохранённого представления над чужим объектом C++26 остаётся самым
ранним уровнем, на котором приведение вычислится при компиляции.

### Идентичность через границы модулей

Приведение по прямой ссылке на объект сравнивает значения
[`scl::type_key`](../meta/type_key.md). Внутри одного модуля это сравнение указателей.
Представление, пришедшее из другого модуля, сравнивается по содержимому ключа, и это
сравнение точное: два одноимённых типа из анонимных пространств имён разных единиц
трансляции различаются по дискриминатору, который ключ хранит.

Два ограничения ключа действуют и здесь:

- Тип, объявленный внутри блока, - локальный класс или тип замыкания - лежит вне
  контракта ключа и может ложно совпасть с одноимённым типом из пространства имён.
  Объявляйте такой тип на уровне пространства имён.
- Ключ не должен пережить модуль, который его создал. Уничтожайте представления,
  созданные внутри разделяемой библиотеки, до её выгрузки.
