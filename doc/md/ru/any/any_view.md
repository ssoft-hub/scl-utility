# Any view

`scl::any_view` описывает объект, который может ссылаться на постоянное значение любого
типа. Тип значения в тип представления не входит: одна функция принимает значение любого
типа, а какой он на самом деле, сообщает само представление. Представление значение только
читает: оно его не создаёт, не копирует и не разрушает, а хранит его адрес вместе с
описанием типа.

- Заголовок: `#include <scl/utility/any/any_view.h>`

## Обзор

Отношение `scl::any_view` к [`scl::any`](any.md) такое же, какое `std::string_view` имеет
к `std::string`. Функция, которой нужно прочитать значение неизвестного типа, принимает
представление и не заставляет вызывающую сторону складывать значение в контейнер.
Копирование и выделение памяти при этом не выполняются.

Представление занимает два указателя и копируется тривиально.

Сослаться оно может на типизированный объект напрямую: тип известен уже при компиляции, его
задаёт
[`scl::type_key`](../meta/type_key.md), поэтому RTTI не требуется, а `type_name()`,
`type_key()`, `has_value()` и само построение представления вычисляются на этапе
компиляции.

Представление называет только тот тип, с которым связано, а `std::any` - такой же тип, как
любой другой. Поэтому представление над ним ссылается на сам `std::any`: `type_name()`
возвращает `"std::any"`, `any_cast<std::any>` возвращает этот же объект, а приведение к любому
другому типу не возвращает ничего. Читать объект, который хранит `std::any`, умеет
[`<scl/utility/any/std_any.h>`](std_any.md), и платит за это только то приведение, которое
называет `std::any`. Ничто в этом заголовке не зависит от настроек сборки.

Читать через представление можно, писать нельзя. Функция `scl::any_cast` возвращает либо
копию значения, либо константную ссылку на него. Запрос неконстантной ссылки или
ссылки на временный объект не компилируется, потому что представление доступа на запись
не даёт.

Представление не хранит значение у себя и не продлевает его жизнь. Оно действительно ровно до
тех пор, пока жив объект, на который оно ссылается, - та же оговорка, что и у
`std::string_view`.

## Возможности

- Ссылается на объект, ничего не копируя, и не даёт доступа на запись.
- Занимает два указателя и копируется тривиально.
- Ссылается на типизированный объект любого типа и не использует RTTI.
- Ссылается на `std::any` как на обычный объект, которым тот и является, - тем же
  конструктором, каким принимает любой другой тип.
- Отвечает на запросы `type_name()`, `type_key()` и `has_value()` в том числе на этапе
  компиляции, начиная с C++20.
- Отдаёт указатель через `any_cast<T>(view *)`; при несовпадении типа возвращается
  `nullptr`, исключение не выбрасывается.
- Отдаёт значение или константную ссылку через `any_cast<T>(view &)`; при несовпадении
  типа выбрасывает `scl::bad_any_cast`.
- Преобразуется из `std::any` неявно, а хранимый им объект читает через
  [`<scl/utility/any/std_any.h>`](std_any.md).

## Справочник по API

### Построение

```cpp
std::string text{"Hello Any!"};

scl::any_view empty{};      // не ссылается ни на какой объект
scl::any_view raw{text};    // ссылается на объект напрямую
scl::any_view alias = raw;  // копируется тривиально
```

Представление принимает только lvalue, то есть именованный объект. Привязка к временному
объекту отвергается компилятором: такое представление стало бы недействительным сразу
после окончания выражения.

`std::any` преобразуется в представление неявно, как любое другое именованное значение:

```cpp
std::any boxed{text};
scl::any_view over_any{boxed};   // ссылается на std::any, а не на строку внутри него
```

Временный `std::any` представление тоже не принимает, поэтому оно не переживёт объект, на
который ссылается.

### Наблюдение

```cpp
std::string text{"Hello Any!"};
scl::any_view raw{text};

raw.has_value();   // true
raw.type_name();   // имя типа std::string; точное написание даёт компилятор,
                   // например "std::basic_string<char>"
raw.type_key();    // scl::type_key, обозначающий std::string
```

`has_value()` возвращает `false` только когда представление пустое. Представление,
ссылающееся на `std::any`, возвращает `true` независимо от того, что этот `std::any`
хранит: представление ссылается на значение - на сам контейнер.

`type_name()` возвращает имя типа, известное при компиляции. Когда представление
ссылается на объект напрямую, это имя самого типа объекта. Когда оно ссылается на
`std::any`, это имя `std::any`, а не имя типа, лежащего внутри.

`type_key()` возвращает [`scl::type_key`](../meta/type_key.md) по значению. Пустое
представление не обозначает никакого типа и возвращает `scl::type_key{}` - ключ, который
не называет ничего. Равенство `type_key().name() == type_name()` выполняется всегда:

```cpp
raw.type_key() == scl::type_key_of<std::string>();      // true
scl::any_view{}.type_key() == scl::type_key{};          // true
```

Вызов `any_cast<std::any>` возвращает сам `std::any` - тот объект, на который ссылается
представление, и тот тип, который для такой привязки уже называют `type_name()` и
`type_key()`. Объект, который хранит `std::any`, читают через
[`<scl/utility/any/std_any.h>`](std_any.md), передав ему сам `std::any`.

### Приведение

Форма с указателем возвращает константный указатель, когда запрошенный тип совпадает с
типом объекта, и `nullptr` в противном случае. Исключений она не выбрасывает:

```cpp
if (auto const * s = scl::any_cast<std::string>(&raw))
    use(*s);   // без копирования
```

Форма со ссылкой возвращает объект по значению или по константной ссылке и выбрасывает
`scl::bad_any_cast`, если тип не совпал. Результат-ссылка связывается с объектом без
копирования:

<!-- snippet: example/any/common/any_common_example.cpp reference_cast -->
```cpp
static void show_reference_cast()
{
    ::std::string const text{"Hello Any!"};

    // Bind through a NAMED view: casting `T const &` through a temporary view
    // would trip GCC's -Wdangling-reference, even though the payload outlives it.
    ::scl::any_view const view{text};

    auto const copy = ::scl::any_cast<::std::string>(view);          // independent copy
    auto const & ref = ::scl::any_cast<::std::string const &>(view); // zero-copy reference

    ::std::cout << "copy == \"" << copy << "\" (own object)\n";
    ::std::cout << "ref  == \"" << ref << "\" bound to source? " << (&ref == &text) << '\n'; // 1
}
```

Форма со ссылкой объявлена только там, где
[`SCL_HAS_EXCEPTIONS`](../preprocessor/exceptions.md) равен `1`. Если исключения
отключены, остаётся форма с указателем, и о несовпадении типа она уже сообщает.

Тот же вызов `scl::any_cast` читает `std::any` напрямую, когда подключён
[`<scl/utility/any/std_any.h>`](std_any.md):

```cpp
std::any boxed{text};
scl::any_cast<std::string>(boxed);        // строка внутри std::any
scl::any_cast<std::string>(&boxed);       // то же самое, указателем

scl::any_view over_any{boxed};
scl::any_cast<std::string>(&over_any);    // nullptr: представление называет std::any
scl::any_cast<std::any const>(&over_any); // сам std::any
```

Тип `scl::bad_any_cast` наследуется от `std::bad_cast` в любой сборке и никогда от
`std::bad_any_cast`. Поэтому обработчик `catch (std::bad_cast const &)` перехватывает его
независимо от настроек сборки, а сам тип не зависит от RTTI.

### Квалификаторы const и volatile

Представление запоминает квалификаторы объекта, к которому его привязали. Приведение
обязано запросить все эти квалификаторы: добавить квалификатор можно, отбросить нельзя.
Квалификатор `const` добавляет само чтение, поэтому на практике запрашивать приходится
только `volatile`:

```cpp
int volatile sensor = 0;
scl::any_view const view{sensor};

scl::any_cast<int>(&view);                 // nullptr: запрос отбросил бы volatile
scl::any_cast<int volatile>(&view);        // int const volatile *
scl::any_cast<int const volatile &>(view); // читает volatile-объект
```

Обратное направление разрешено всегда: запрос с `volatile` проходит и по объекту без
квалификаторов.

Собственные квалификаторы представления в запросе не участвуют: они относятся к самому
представлению, а не к объекту, на который оно ссылается.

```cpp
int number = 0;
scl::any_view volatile view{number};

scl::any_cast<int>(&view);   // читает нормально: у объекта квалификаторов нет
```

### Вычисление на этапе компиляции

Построение представления и запросы `type_name()`, `type_key()` и `has_value()` выполняются
на этапе компиляции, начиная с C++20. Приведение тоже, но не к любому объекту. Восстановить
типизированный указатель из `void const *` на этапе компиляции нельзя до P2738 (C++26), а
преобразовать указатель на базовый тип в указатель на сам объект можно и сейчас - значит,
рядом со значением должен находиться объект известного библиотеке класса.

У значения, которое хранит [`scl::any`](any.md), такой объект уже есть: контейнер
размещает значение внутри служебного объекта, и `any_cast` получает доступ к значению,
преобразуя указатель на базовый тип в указатель на сам объект. Поэтому представление над
`scl::any` читается на этапе компиляции без оговорок, в том числе сохранённое в переменной:

```cpp
constexpr int read()
{
    scl::any const value{42};
    scl::any_view const view{value};

    return *scl::any_cast<int>(&view);
}

static_assert(read() == 42);
```

Рядом с обычным объектом ничего подобного нет, и представление этого не исправит: оно
объектом не владеет, а держать нужный объект внутри себя не может - пришлось бы либо
копировать значение, либо брать память, которую необладающему виду некому вернуть. Такой
объект объявляет вызывающая сторона, и называется он [`scl::any_anchor`](any_anchor.md):

```cpp
static constexpr int probe = 42;
static constexpr scl::any_anchor anchor{probe};
constexpr scl::any_view view{anchor};

static_assert(*scl::any_cast<int>(&view) == 42);
```

Без якоря приведение к обычному объекту в константном выражении не компилируется. Неверного
значения оно не вернёт. Во время работы программы якорь ни на что не влияет: представление
записывает то же статическое описание типа, что и при обычной привязке.

Начиная с C++26 якорь не нужен: восстановление указателя из `void const *` само становится
константным выражением, и приведение вычисляется для любого объекта. Тип остаётся в
интерфейсе, чтобы код, написанный под C++20, продолжал собираться.

### Идентичность через границы модулей

Приведение по прямой ссылке на объект сравнивает значения
[`scl::type_key`](../meta/type_key.md). Внутри одного модуля это сравнение указателей.
Представление, пришедшее из другого модуля, сравнивается по содержимому ключа, и это
сравнение точное: два одноимённых типа из анонимных пространств имён разных единиц
трансляции различаются по дискриминатору, который ключ хранит.

Два ограничения ключа действуют и здесь:

- Тип, объявленный внутри блока, - локальный класс или тип замыкания - лежит вне
  контракта ключа и может ложно совпасть с одноимённым типом из пространства имён.
  Объявляйте такой тип на уровне пространства имён.
- Ключ не должен пережить модуль, который его создал. Уничтожайте представления,
  созданные внутри разделяемой библиотеки, до её выгрузки.
