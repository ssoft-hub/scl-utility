# Any arg

Представление для параметра метода — над `std::any`, типизированным значением
или существующим `any_view`.

- Заголовок: `#include <scl/utility/any/any_arg.h>`

## Обзор

`scl::any_arg` — компаньон [`scl::any_view`](any_view.md) для параметра метода:
привязывается к lvalue **и** rvalue любой константности и действителен только в
пределах вызова, в который передан. Функция принимает его параметром по значению,
чтобы получить разнородный аргумент — включая временный объект — без затрат на
выделение памяти. Как и представление, он занимает два указателя и тривиально
копируем, а в отличие от представления его приведения вычислимы на этапе
компиляции (см. [Вычисление на этапе компиляции](#вычисление-на-этапе-компиляции)).

Два типа разделяют роли, которые `std::string_view` пытается совмещать.
`any_view` — *хранимый*: его можно держать в поле или контейнере, поэтому он
принимает только lvalue — привязанный временный объект повис бы. `any_arg` —
*только для параметра*: временный аргумент по построению переживает вызов,
поэтому rvalue разрешены, но взамен объект нельзя удерживать после вызова.

По правам доступа пара похожа на `reference`/`const_reference`: `const any_arg`
читает ровно как `any_view` — это буквально одно правило покрытия
квалификаторов. Тем не менее `any_view` — не «`const any_arg`», и заменить его
константностью нельзя:

- `const` у параметра, передаваемого по значению, не входит в тип функции —
  `void f(any_arg)` и `void f(any_arg const)` имеют одну сигнатуру, поэтому
  контракт «только чтение» через `const` невидим вызывающей стороне. Различие
  `f(any_view)`/`f(any_arg)` система типов проверяет, `const` — нет.
- Отказ `any_view` от rvalue — ошибка компиляции на любом компиляторе.
  `const any_arg` временный объект связывает, а диагностика висячей ссылки
  (`SCL_LIFETIMEBOUND`) есть только у Clang — GCC и MSVC компилируют молча.
- Хранить `const any_arg` в поле не выйдет: полю нужно присваивание, а `const`
  его запрещает. Неконстантный же `any_arg` в поле снова открыл бы запись.

Ссылаться `any_arg` может на то же, что и `any_view`: на типизированное значение
напрямую, без RTTI, или на `std::any` (только сборки с RTTI). Переданный
`any_view` отдаёт свой объект — `any_arg` ссылается на тот же объект, а не на
представление. Запросы идентичности ведут себя одинаково.

Доступ шире, чем у представления. `any_view` — только для чтения всегда;
`any_arg` дополнительно даёт запись, но лишь когда аргумент был привязан к
объекту без cv-квалификаторов. Это то же правило покрытия квалификаторов, что и
в `any_view`: приведение обязано запрашивать все квалификаторы объекта, а запись
не запрашивает ни одного, поэтому её получает только объект без квалификаторов.

Хранение затруднено на уровне API: у `any_arg` нет конструктора по умолчанию и
нет присваивания. Копирующий конструктор остаётся — передача параметра по
значению требует его. Параметры конструкторов аннотированы
(`SCL_LIFETIMEBOUND`), поэтому Clang сообщает об `any_arg`, покидающем область
жизни объекта, на который он ссылается.

## Возможности

- Привязка к lvalue и rvalue любой константности — безопасно для параметра
- Невладеющий, шириной в два указателя, тривиально копируемый
- Те же источники и запросы идентичности, что у `any_view`; `constexpr` на C++20
- Приведение через указатель `any_cast<T>(arg*)` — `noexcept`, null при несовпадении
- Приведение к ссылке/значению `any_cast<T>(arg)` — бросает `scl::bad_any_cast`
  при несовпадении
- Приведения вычисляются на этапе компиляции на C++20, если аргумент — параметр, и в
  любой позиции, как только компилятор реализует P2738 (C++26)
- Запись через `any_cast<T>(arg*)` или `any_cast<T &>` по объекту без
  квалификаторов
- Неявное преобразование в `any_view` для делегирования; без пустого состояния и
  присваивания

## Справочник по API

### Конструирование

```cpp
void foo(scl::any_arg value);

std::string text{"Hello Any!"};
foo(text);                        // lvalue, ссылка напрямую
foo(std::string{"temporary"});    // rvalue — переживает вызов, ОК
foo(std::any{text});              // временный std::any (только сборки с RTTI)

scl::any_view view{text};
foo(view);                        // принимает объект существующего представления
```

Объявить `any_arg` без аргумента нельзя: конструктора по умолчанию нет, а раз
нет и присваивания, такой экземпляр остался бы пустым навсегда — наполнить его
было бы нечем. Копирование при этом доступно: копирующий конструктор — это то,
чем работает передача параметра по значению. Привязка задаётся один раз, при
создании, и дальше не меняется. При этом `has_value()` всё же может вернуть `false`: пустой
`std::any` и `any_arg`, принявший объект пустого `any_view`, сообщают о
пустоте *содержимого* — аргумент был передан, просто ссылается на пустую
обёртку.

### Наблюдение

```cpp
void foo(scl::any_arg value)
{
    value.has_value();
    value.type_name();   // имя типа, на который ссылается; "std::any" для std::any
    value.type_key();    // scl::type_key const *, идентифицирующий этот тип
}
```

Идентичность работает ровно как у представления, в том числе через границу
модуля: см. [any_view](any_view.md#идентичность-через-границу-модуля).

### Чтение

Форма с указателем возвращает `Type *` при совпадении типа и `nullptr` иначе;
указатель ссылается на объект аргумента. Для чтения запрашивайте `const`: такой
запрос проходит и по константному объекту:

```cpp
if (auto const * s = scl::any_cast<std::string const>(&value))
    use(*s);   // без копирования
```

Форма со ссылкой возвращает копию значения или `const`-ссылку, а при несовпадении
бросает исключение:

```cpp
std::string copy = scl::any_cast<std::string>(value);                 // копия наружу
std::string const & ref = scl::any_cast<std::string const &>(value);  // без копирования
```

Чтобы сохранить значение после вызова — копируйте его наружу; никогда не
удерживайте сам `any_arg` (или полученный из него `any_view`), если аргумент был
временным.

### Запись

Аргумент понимает запрос буквально. Форма с указателем возвращает `Type *`,
то есть какую квалификацию запросили — такую и получите, и только если запрос
покрывает квалификаторы, с которыми был связан объект:

```cpp
int *       w = scl::any_cast<int>(&value);       // только объект без квалификаторов
int const * r = scl::any_cast<int const>(&value); // и константный тоже
```

Этим аргумент отличается от `any_view`, который только читает: там запрос может
называть любую квалификацию, но результат всегда получает `const`.

```cpp
void bump(scl::any_arg value)
{
    if (auto * number = scl::any_cast<int>(&value))
        ++*number;                              // запись видна вызывающей стороне
}

int counter = 0;
bump(counter);            // counter == 1
int const frozen = 0;
bump(frozen);             // отказ: nullptr, объект константный
```

Форма со ссылкой выражает тот же выбор ссылочным типом — `any_cast<int &>` пишет,
`any_cast<int const &>` читает — и бросает `scl::bad_any_cast` там, где форма с
указателем возвращает `nullptr`. Правило всюду одно: приведение обязано
запрашивать все квалификаторы объекта, а запись не запрашивает ни одного, поэтому
её получает только объект без квалификаторов.

Со ссылкой на `std::any` всё так же: запись доходит до объекта внутри, если сам
`std::any` был неконстантным. `volatile std::any` не поддерживается — у
`std::any` нет `volatile`-квалифицированных членов, а `std::any_cast` не
принимает `volatile`-указатель.

Правило покрытия квалификаторов касается не только объекта, но и самого
`any_arg`: `const`/`volatile` у аргумента — это тоже квалификаторы, которые
запрос обязан покрыть. Поэтому `const any_arg` не даёт записи, даже если объект
внутри вообще без квалификаторов:

```cpp
int value = 0;
scl::any_arg const arg{value};
scl::any_cast<int>(&arg);         // nullptr: аргумент const, запрос не покрывает
scl::any_cast<int const>(&arg);   // читает нормально
```

`volatile any_arg` симметрично требует `volatile` в запросе, независимо от
квалификаторов самого объекта.

Через `any_view` запись недоступна вовсе — неявное преобразование
`any_view` → `any_arg` её не открывает, поэтому представление остаётся строго
только для чтения.

### Вычисление на этапе компиляции

В отличие от представления, приведения аргумента сворачиваются на этапе компиляции
уже на базовом уровне C++20:

```cpp
constexpr int doubled(scl::any_arg value)
{
    auto const * number = scl::any_cast<int const>(&value);
    return (number != nullptr) ? *number * 2 : 0;
}

static_assert(doubled(21) == 42);
```

Работает это за счёт якоря. Восстановить типизированный указатель из `void const *`
на этапе компиляции нельзя до P2738 (C++26), а приведение вниз по иерархии классов
законно. Якорь - это и есть такой производный класс: дескриптор, который вдобавок
несёт типизированный указатель. Конструктор принимает якорь, созданный вызывающей
стороной на каждую привязку, а `any_cast` добирается до объекта, приводя дескриптор
вниз. Именно то, что якорь является дескриптором, сохраняет ширину в два указателя:
указатель, который представление и так тратит на дескриптор, служит обеим ролям.

Якорь - временный объект вызывающей стороны, поэтому живёт ровно столько, сколько
длится вызов, ради которого создан. Аргумент - это в точности такая сущность, и по
этой же причине представление так не умеет. **Якорь берёт только вычисление на этапе
компиляции.** Во время выполнения конструктор записывает статический дескриптор,
поэтому `any_arg` в любой позиции - локальная переменная, поле - ведёт себя ровно
так же, как вёл бы без всего этого механизма.

Отсюда границы применимости:

- Аргумент должен быть **параметром**. Если `any_arg` - локальная переменная, поле
  или элемент агрегата, якорь уже разрушен, поэтому приведение - а вместе с ним и
  запрос идентичности - останавливается с диагностикой, а не возвращает неверный
  результат. Надёжно диагностирует это только Clang: GCC и MSVC продлевают временный
  объект дольше и такой код принимают, так что их согласие гарантией не считайте.
- `constexpr`-**переменной** типа `any_arg` не бывает: её значение содержало бы
  указатель на временный объект, что константному выражению запрещено. Оформляйте
  работу `constexpr`-функцией.
- У источника `std::any` и у объекта, перенятого от `any_view`, якоря не бывает,
  поэтому их приведения выполняются во время выполнения - так же, как у
  представления.
- Времени выполнения всё это не касается. Там работает любая позиция и отвечает
  любой запрос, ширина - те же два указателя, а стоимость - та же, что у
  представления.

Стоит знать об особенности одного компилятора, замеренной на GCC 13.1: сравнение
адреса временного объекта с `nullptr` он признаёт неконстантным, если объемлющее
константное выражение находится в области видимости пространства имён. При вычислении
на этапе компиляции дескриптор — как раз такой временный объект, и его проверяет
каждое приведение, поэтому там отвергается вся проверка целиком. Тот же код в теле
функции принимается; Clang и MSVC принимают любое размещение. Размещайте такую
проверку внутри функции:

```cpp
void check()
{
    static_assert(doubled(21) == 42);   // тело функции: принимается везде
}
```

### Когда компилятор сворачивает приведение сам

Все перечисленные границы принадлежат якорю, а не типу. Если `__cpp_constexpr`
сообщает о P2738 (C++26), заголовок выбирает другую ветку: якорь не компилируется
вовсе, конструктор записывает тот же статический дескриптор, что и представление, а
приведение восстанавливает объект из `void const *` напрямую. На стороне вызова не
меняется ничего, а список выше снимается целиком — приведение сворачивается для
`any_arg` в любой позиции, по референту, перенятому от `any_view`, и в области
видимости пространства имён на любом компиляторе, включая GCC. `any_view` получает
вычислимые на этапе компиляции приведения тогда же и по той же причине, без единой
правки в собственном коде.

Ни ширина, ни раскладка `any_arg` от стандарта не зависят; ветка меняет объявление
одного параметра конструктора, который вызывающая сторона никогда не передаёт. Как и
со стандартной библиотекой, собирайте один бинарник целиком по одному `-std`.

Ветку покрывает случай `AnyArgTest.ConstexprCastReachesAnyPositionOnceTheVoidCastFolds`.
На сборке C++20 он отмечается как *пропущенный* и превращается в настоящие проверки,
как только проект собирается по C++26.

### Делегирование

```cpp
void inner(scl::any_view value);

void foo(scl::any_arg value)
{
    inner(value);   // неявное преобразование any_arg -> any_view
}
```
