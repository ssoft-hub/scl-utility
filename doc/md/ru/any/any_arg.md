# Any arg

`scl::any_arg` описывает объект, который может ссылаться на значение любого типа -
постоянное или изменяемое - на время одного вызова. Функция принимает его по значению,
чтобы прочитать, а иногда и изменить аргумент, тип которого известен только во время
выполнения, ничего не копируя и не выделяя памяти.

- Заголовок: `#include <scl/utility/any/any_arg.h>`

## Обзор

`scl::any_arg` дополняет [`scl::any_view`](any_view.md). Оба ссылаются на чужой объект,
занимают два указателя и копируются тривиально, но у них разные области применения.

Представление можно хранить: положить в поле, в контейнер, вернуть из функции. Именно
поэтому оно принимает только именованный объект. Если бы оно связывало временный объект,
то пережило бы его и стало недействительным.

Аргумент хранить нельзя, зато он связывает и именованный, и временный объект. Временный
объект, переданный в вызов, живёт до конца этого вызова, поэтому параметр им пользуется
безопасно.

Отсюда вопрос: нельзя ли обойтись одним типом и выразить разницу словом `const`, объявив
параметр как `any_arg const`? Нет, по трём причинам.

Во-первых, `const` у параметра, передаваемого по значению, не входит в тип функции.
Объявления `void f(any_arg)` и `void f(any_arg const)` описывают одну и ту же функцию,
поэтому вызывающая сторона по сигнатуре не увидит, читает функция аргумент или пишет в
него. Различие между `f(any_view)` и `f(any_arg)` система типов проверяет, различие по
`const` - нет.

Во-вторых, `any_view` отвергает временный объект на любом компиляторе, а `const any_arg`
его свяжет. Предупреждение о том, что ссылка окажется висячей, выдаёт только Clang; GCC и
MSVC компилируют такой код молча.

В-третьих, `const any_arg` невозможно положить в поле: полю нужно присваивание, а `const`
его запрещает. Неконстантный же `any_arg` в поле снова открыл бы запись.

Ссылаться `any_arg` может на то же, на что и представление: на типизированный объект
напрямую, без RTTI, или на `std::any` - последнее только в сборках с RTTI. Переданное
представление отдаёт ему свой объект, поэтому аргумент ссылается на тот же объект, а не на
представление. Запросы идентичности у обоих типов ведут себя одинаково.

Права доступа у аргумента шире. Представление только читает. Аргумент читает всегда, а
писать может тогда, когда его связали с объектом без квалификаторов `const` и `volatile`.

Хранить аргумент мешает и сам интерфейс: у `scl::any_arg` нет ни конструктора по
умолчанию, ни присваивания. Копирующий конструктор остаётся, потому что без него
невозможна передача параметра по значению. Параметры конструкторов помечены атрибутом
привязки к времени жизни, поэтому Clang предупреждает, когда аргумент покидает область,
где живёт объект.

## Возможности

- Связывает и именованный, и временный объект любой константности - для параметра это
  безопасно.
- Значение у себя не хранит, занимает два указателя и копируется тривиально.
- Ссылается на то же, что и представление, и отвечает на те же запросы идентичности; они
  вычисляются на этапе компиляции, начиная с C++20.
- Отдаёт указатель через `any_cast<T>(arg *)`; при несовпадении типа возвращается
  `nullptr`, исключение не выбрасывается.
- Отдаёт значение или ссылку через `any_cast<T>(arg)`; при несовпадении типа выбрасывает
  `scl::bad_any_cast`.
- Разрешает запись через `any_cast<T>(arg *)` или `any_cast<T &>`, если объект не имеет
  квалификаторов.
- Выполняет приведения на этапе компиляции уже на C++20, когда он стоит в позиции
  параметра, и в любой позиции - на компиляторе, реализовавшем P2738 (C++26).
- В `scl::any_view` не преобразуется вовсе: представление можно хранить, аргумент
  нельзя.

## Справочник по API

### Построение

```cpp
void foo(scl::any_arg value);

std::string text{"Hello Any!"};
foo(text);                        // именованный объект, ссылка напрямую
foo(std::string{"temporary"});    // временный объект переживёт вызов, это допустимо
foo(std::any{text});              // временный std::any, только в сборках с RTTI

scl::any_view view{text};
foo(view);                        // принимает объект представления, а не само представление
```

Объявить `any_arg` без аргумента нельзя: конструктора по умолчанию нет. Присваивания тоже
нет, поэтому пустой экземпляр остался бы пустым навсегда - наполнить его было бы нечем.
Копирование при этом доступно, ведь копирующий конструктор и выполняет передачу параметра
по значению. Привязка задаётся один раз, при создании, и больше не меняется.

При этом `has_value()` всё же может ответить `false`. Так отвечает аргумент, связанный с
пустым `std::any` или принявший объект пустого представления: аргумент передан, но
содержимого у источника нет.

### Наблюдение

```cpp
void foo(scl::any_arg value)
{
    value.has_value();
    value.type_name();   // имя типа объекта; для std::any отвечает "std::any"
    value.type_key();    // scl::type_key const *, обозначающий этот тип
}
```

Идентичность работает так же, как у представления, включая сравнение через границу
модуля: см. [any_view](any_view.md#идентичность-через-границы-модулей).

### Чтение

Форма с указателем возвращает `Type *`, когда запрошенный тип совпадает с типом объекта, и
`nullptr` в противном случае. Указатель ведёт на объект вызывающей стороны. Для чтения
запрашивайте тип с `const`: такой запрос проходит и по константному объекту:

```cpp
if (auto const * s = scl::any_cast<std::string const>(&value))
    use(*s);   // без копирования
```

Форма со ссылкой возвращает копию значения или константную ссылку, а при несовпадении типа
выбрасывает исключение:

```cpp
std::string copy = scl::any_cast<std::string>(value);                 // копия наружу
std::string const & ref = scl::any_cast<std::string const &>(value);  // без копирования
```

Формы со ссылкой и со значением объявлены только там, где
[`SCL_HAS_EXCEPTIONS`](../preprocessor/exceptions.md) равен `1`. Если исключения
отключены, остаётся форма с указателем, и о несовпадении типа она уже сообщает.

Чтобы сохранить значение после вызова, скопируйте его наружу. Не удерживайте сам `any_arg`
и полученное из него представление, если аргумент был связан с временным объектом.

### Запись

Аргумент понимает запрос буквально: форма с указателем возвращает `Type *` с той
квалификацией, которую запросили. Запрос проходит, только если он покрывает квалификаторы
объекта:

```cpp
int *       w = scl::any_cast<int>(&value);       // только объект без квалификаторов
int const * r = scl::any_cast<int const>(&value); // и константный объект тоже
```

Этим аргумент отличается от представления. Представление только читает, поэтому запрос там
может называть любую квалификацию, но результат всегда получает `const`.

```cpp
void bump(scl::any_arg value)
{
    if (auto * number = scl::any_cast<int>(&value))
        ++*number;                              // запись видна вызывающей стороне
}

int counter = 0;
bump(counter);            // counter становится равен 1
int const frozen = 0;
bump(frozen);             // запись не выполняется: объект константный, получен nullptr
```

Форма со ссылкой выражает тот же выбор ссылочным типом: `any_cast<int &>` пишет,
`any_cast<int const &>` читает. Там, где форма с указателем возвращает `nullptr`, форма со
ссылкой выбрасывает `scl::bad_any_cast`.

Правило одно и то же для всей группы: приведение обязано запросить все квалификаторы
объекта. Запись не запрашивает ни одного, поэтому её получает только объект без
квалификаторов.

Со ссылкой на `std::any` действует то же правило: запись доходит до объекта внутри, если
сам `std::any` неконстантный. Тип `volatile std::any` не поддерживается, потому что у
`std::any` нет членов с квалификатором `volatile`, а `std::any_cast` не принимает
указатель на `volatile`.

Правило покрытия касается не только объекта, но и самого аргумента. Квалификаторы `const`
и `volatile` у переменной типа `any_arg` тоже нужно запросить. Поэтому `const any_arg` не
даёт записи, даже если объект внутри вообще без квалификаторов:

```cpp
int value = 0;
scl::any_arg const arg{value};

scl::any_cast<int>(&arg);         // nullptr: аргумент константный, запрос его не покрывает
scl::any_cast<int const>(&arg);   // читает нормально
```

Переменная `volatile any_arg` симметрично требует `volatile` в запросе, независимо от
квалификаторов самого объекта.

Через представление запись недоступна вовсе. Неявное преобразование `any_arg` в
`any_view` её не открывает, поэтому представление остаётся строго только для чтения.

### Вычисление на этапе компиляции

Приведения аргумента вычисляются на этапе компиляции уже на C++20, чего представление не
умеет:

```cpp
constexpr int doubled(scl::any_arg value)
{
    auto const * number = scl::any_cast<int const>(&value);
    return (number != nullptr) ? *number * 2 : 0;
}

static_assert(doubled(21) == 42);
```

Работает это за счёт вспомогательного объекта, который библиотека называет якорем. Якорь -
это описание типа, дополнительно несущее типизированный указатель на объект. Восстановить
типизированный указатель из `void const *` на этапе компиляции нельзя до P2738 (C++26), а
приведение указателя вниз по иерархии классов законно и сейчас. Якорь как раз и есть такой
производный класс: конструктор аргумента принимает якорь, созданный вызывающей стороной на
каждую привязку, а `any_cast` добирается до объекта, приводя описание типа вниз. Ширина в
два указателя при этом сохраняется: указатель, который аргумент и так тратит на описание
типа, служит обеим ролям.

Якорь - временный объект вызывающей стороны, поэтому он живёт ровно столько, сколько
длится вызов, ради которого создан. Параметр функции - это в точности такая сущность,
поэтому представление, которое можно хранить сколько угодно, так работать не может.

Якорь участвует только в вычислении на этапе компиляции. Во время работы программы
конструктор записывает статическое описание типа, поэтому `any_arg` в любой позиции - в
локальной переменной, в поле - ведёт себя ровно так же, как вёл бы без этого механизма.

Отсюда следуют границы применимости.

- Аргумент должен быть **параметром**. Если `any_arg` объявлен локальной переменной, полем
  или элементом агрегата, якорь к моменту приведения уже разрушен. Тогда приведение - а
  вместе с ним и запрос идентичности - останавливается с диагностикой компилятора, а не
  возвращает неверный результат. Надёжно диагностирует это только Clang: GCC и MSVC
  продлевают жизнь временного объекта дольше и такой код принимают, поэтому их согласие
  гарантией не считайте.
- Переменной `constexpr` типа `any_arg` не бывает: её значение содержало бы указатель на
  временный объект, а константному выражению это запрещено. Оформляйте работу
  `constexpr`-функцией.
- У `std::any` и у объекта, полученного от представления, якоря нет, поэтому их приведения
  выполняются во время работы программы - так же, как у представления.
- Времени работы программы всё сказанное не касается. Там работает любая позиция и
  отвечает любой запрос, ширина остаётся в два указателя, а стоимость совпадает со
  стоимостью представления.

Стоит знать об особенности GCC 13.1. Этот компилятор считает неконстантным сравнение
адреса временного объекта с `nullptr`, если объемлющее константное выражение находится в
области видимости пространства имён. При вычислении на этапе компиляции описание типа как
раз и является таким временным объектом, а проверяет его каждое приведение, поэтому GCC
отвергает всю проверку целиком. Тот же код в теле функции он принимает. Clang и MSVC
принимают любое размещение:

```cpp
void check()
{
    static_assert(doubled(21) == 42);   // в теле функции принимается всеми компиляторами
}
```

### Когда компилятор сворачивает приведение сам

Все перечисленные границы принадлежат якорю, а не самому типу. Если макрос
`__cpp_constexpr` сообщает о поддержке P2738 (C++26), заголовок выбирает другую ветку:
якорь не компилируется вовсе, конструктор записывает то же статическое описание типа, что
и у представления, а приведение восстанавливает объект из `void const *` напрямую.

На стороне вызова не меняется ничего, а перечисленные ограничения снимаются целиком.
Приведение сворачивается для `any_arg` в любой позиции, для объекта, полученного от
представления, и в области видимости пространства имён на любом компиляторе, включая GCC.
Представление получает вычислимые на этапе компиляции приведения тогда же и по той же
причине, без единой правки в собственном коде.

Ширина и раскладка `any_arg` от стандарта не зависят: ветка меняет объявление одного
параметра конструктора, который вызывающая сторона никогда не передаёт. Как и со
стандартной библиотекой, собирайте один двоичный файл целиком с одним значением `-std`.

Эту ветку покрывает тест `AnyArgTest.ConstexprCastReachesAnyPositionOnceTheVoidCastFolds`.
При сборке по C++20 он помечается как пропущенный и превращается в настоящие проверки, как
только проект собирается по C++26.

### Передача значения дальше

Аргумент передаётся дальше как аргумент: он копируем, а копия ссылается на тот же
объект.

```cpp
void inner(scl::any_arg value);

void foo(scl::any_arg value)
{
    inner(value);   // копия аргумента, тот же объект
}
```

В `any_view` аргумент не преобразуется - ни именованный, ни временный:

```cpp
scl::any_view stored = value;   // не компилируется
```

Причина в том, что типы различаются правом на хранение. Представление хранить можно,
поэтому оно и отказывается связывать временный объект. Аргумент хранить нельзя: он
действителен только в пределах вызова, а объект, на который он ссылается, вызывающая
сторона могла создать временным. Преобразование выдало бы хранимое представление на
объект, время жизни которого кончается вместе с вызовом.

Поэтому функция, которая только читает значение на время вызова, объявляет параметр
`any_arg`. Параметр `any_view` объявляет та, которой представление можно доверить
хранить, - и вызывающая сторона строит его сама, из объекта, время жизни которого
она контролирует.
