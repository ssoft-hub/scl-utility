# Any anchor

`scl::any_anchor` - вспомогательный объект, который вызывающая сторона объявляет рядом со
значением, чтобы [`scl::any_view`](any_view.md) и [`scl::any_arg`](any_arg.md) прочитали это
значение на этапе компиляции.

- Заголовок: `#include <scl/utility/any/any_anchor.h>`

## Обзор

`any_cast` отдаёт типизированный указатель. Восстановить такой указатель из `void const *`
на этапе компиляции нельзя до P2738 (C++26), а преобразовать указатель на базовый тип в
указатель на сам объект можно и сейчас. Для второго способа рядом со значением должен
находиться объект известного библиотеке класса, и продержать его требуется столько же,
сколько живёт представление.

Якорь и есть такой объект: он хранит описание типа значения и типизированный указатель на
само значение. Объявляет якорь вызывающая сторона, поэтому за время его жизни отвечает та же
сторона, что и за время жизни самого значения.

Значению, которое хранит [`scl::any`](any.md), якорь не нужен: контейнер и так размещает
значение внутри служебного объекта, и `any_cast` получает доступ к значению, преобразуя
указатель на базовый тип в указатель на сам объект.

Во время работы программы якорь ни на что не влияет: представление, построенное через него,
записывает то же статическое описание типа, что и при обычной привязке, поэтому ни ширина
представления, ни стоимость приведения не меняются.

## Возможности

- Позволяет прочитать обычный объект через представление и аргумент на этапе компиляции,
  начиная с C++20.
- Снимает с аргумента требование быть параметром: якорь живёт столько, сколько живёт
  объявившая его переменная.
- Выводит тип значения вместе с квалификаторами, поэтому `scl::any_anchor bound{value};`
  пишется без аргумента шаблона.
- Ничем не владеет и время жизни значения не продлевает.
- Копируется, перемещается и разрушается так, как определяет компилятор по умолчанию;
  каждая из этих операций выполняется и на этапе компиляции.
- Во время работы программы не стоит ничего: ни ширины представления, ни лишнего действия
  при приведении.

## Справочник по API

### Построение

```cpp
int probe = 42;

scl::any_anchor bound{probe};       // scl::any_anchor<int>
scl::any_view const view{bound};    // представление ссылается на probe, а не на якорь
```

Тип значения выводится вместе с квалификаторами: якорь над `int const` отличается от якоря
над `int`, и права на запись у аргумента следуют из этого различия так же, как при обычной
привязке.

Представление и аргумент строятся из якоря неявно, поэтому якорь пишется там же, где
написали бы само значение.

### Чтение на этапе компиляции

Внутри `constexpr`-функции:

```cpp
constexpr int read()
{
    int const probe = 42;
    scl::any_anchor const bound{probe};
    scl::any_view const view{bound};

    return *scl::any_cast<int>(&view);
}

static_assert(read() == 42);
```

В переменной со статическим временем жизни, включая массив представлений:

```cpp
static constexpr int one = 1;
static constexpr int two = 2;

static constexpr scl::any_anchor anchored_one{one};
static constexpr scl::any_anchor anchored_two{two};

constexpr std::array<scl::any_view, 2> views{anchored_one, anchored_two};

static_assert(*scl::any_cast<int>(&views[1]) == 2);
```

Аргумент читается и тогда, когда объявлен переменной, а не параметром. Якорь, который
библиотека создаёт сама для позиции параметра, к моменту приведения уже разрушен, а
объявленный вручную жив:

```cpp
constexpr int doubled()
{
    int probe = 21;
    scl::any_anchor const bound{probe};
    scl::any_argument const subject{bound};

    *scl::any_cast<int>(&subject) *= 2;

    return probe;
}

static_assert(doubled() == 42);
```

### Время жизни

Якорь не владеет значением и не продлевает его жизнь. Представление, построенное через якорь,
ссылается ещё и на сам якорь, поэтому **и значение, и якорь обязаны пережить каждое
представление, привязанное через них**. Правило то же, что и при обычной привязке, только
следить теперь надо за двумя объектами.

### Границы

Без якоря приведение к обычному объекту в константном выражении не компилируется. Неверного
значения оно не вернёт.

Якорь не отменяет остальных ограничений: `std::any` в константном выражении не строится
вовсе, а `constexpr`-переменной типа `scl::any` не бывает, потому что память, взятую на этапе
компиляции, обязательно освободить внутри того же вычисления.

### C++26

Начиная с C++26 якорь не нужен: восстановление указателя из `void const *` само становится
константным выражением, и приведение вычисляется для любого объекта. Тип остаётся в публичном
интерфейсе, чтобы код, написанный под C++20, продолжал собираться без правок.
