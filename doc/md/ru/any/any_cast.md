# Any cast

`scl::any_cast` - единственное приведение, которое предлагает группа Any. Чем различаются
типы, которым оно служит, сообщает `scl::any_cast_traits`: сторонний тип может его
специализировать и тем самым присоединиться.

- Заголовок: `#include <scl/utility/any/any_cast.h>`

## Обзор

Чтение стёртого значения складывается из двух решений, и принимаются они в разных местах.

**Тип результата** следует из запрошенного написания и правила доступа источника, и больше ни
из чего. Источник, который читает, добавляет `const` к каждому запросу, поэтому
[`any_view`](any_view.md) возвращает значение типа `T const *`, как бы вызывающая сторона ни
написала запрос. Источник, который пишет, ничего не добавляет, поэтому
[`any_mutable_view`](any_mutable_view.md) и [`any_arg`](any_arg.md) возвращают значение типа
`T *`. [`any`](any.md) не относится ни к тем, ни к другим: он держит объект внутри себя,
поэтому его собственная константность доходит до объекта, и для константного контейнера тип
результата равен `T const *`.

**Вернётся ли что-нибудь** следует из привязки. Запрос выполняется только там, где покрывает
все квалификаторы, с которыми был связан объект. Поэтому запрос, не называющий ни `const`,
ни `volatile`, просит записи и доходит только до объекта, связанного без обоих. Решения
независимы: запрос может называть тип, который источник умеет назвать, и всё равно вернуть
`nullptr`, потому что привязка несёт квалификатор, пропущенный запросом.

Первое решение сообщает трейт. Второе - одно правило, общее для всех источников.

## Возможности

- Одно приведение для любого источника: представление, контейнер, `std::any` или сторонний
  тип.
- Написание запроса задаёт тип результата, привязка - будет ли запрос выполнен.
- Отдаёт указатель без исключений, привязывает ссылку без копии либо копирует наружу.
- Отвергает тип без специализации в точке вызова, а не внутри приведения.
- Открывается новому типу одной специализацией, без добавления перегрузок в `namespace scl`.

## Справочник по API

### Общие точки входа

```cpp
int value = 42;
scl::any_mutable_view const source{value};

scl::any_cast<int>(&source);        // int *, nullptr при несовпадении, без исключений
scl::any_cast<int &>(source);       // привязывает объект, без копии
scl::any_cast<int>(source);         // копия объекта
```

Форма с указателем возвращает `nullptr` и для нулевого указателя, и при несовпадении типа, и
при квалификаторе, который запрос не покрывает. Обе ссылочные формы выбрасывают
`scl::bad_any_cast` там, где форма с указателем вернула бы `nullptr`, и объявлены только
там, где [`SCL_HAS_EXCEPTIONS`](../preprocessor/exceptions.md) равно `1`.

Привязывающая форма связана по времени жизни: результат ссылается внутрь объекта, доступ к
которому держит только источник. Форма-копия не связана, поскольку результат - самостоятельный
объект. Копирование просит чтение, поэтому оно объявляется для типа, который можно скопировать
с константного объекта, либо когда источник отдаёт объект перемещением: конструктор
копирования, принимающий неконстантную ссылку, изменял бы источник копии через трейт, отдающий
запись. Просить читающий источник привязать неконстантную ссылку не компилируется: его правило
добавляет `const`, и отказ записан в ограничении, а не встречается при преобразовании.

Источник, у которого в точке вызова нет имени, читается перемещением объекта наружу, если его
трейт объявляет `movable_tag`, а написание просит объект, а не ссылку:

```cpp
scl::any_cast<std::string>(scl::any{text});          // перемещён из контейнера
scl::any_cast<std::string>(scl::any_view{text});     // скопирован: представление не владеет
scl::any_cast<std::string>(stored);                  // скопирован: имя означает, что объект держат
```

Любой другой источник читается копированием, а именованный - независимо от того, что объявляет
его трейт. Перемещение наружу поэтому заявляет источник, а не просит вызывающая сторона, оно
не требует отдельной перегрузки, и только так читается тип, который перемещается и не
копируется.

### Что сообщает каждый источник

| Источник | Запрос для написания `T` | Отвергает |
|---|---|---|
| [`any_view`](any_view.md) | `T const` - читает | запрос неконстантной ссылки |
| [`any_mutable_view`](any_mutable_view.md) | `T` - пишет | константный объект при связывании |
| [`any_arg`](any_arg.md) | `T` - доступ называет вызывающая сторона | ничего |
| [`any`](any.md) | `T const` для константного контейнера, иначе `T` | `volatile`-контейнер |
| `std::any` | `T const` для константного `std::any`, иначе `T`, см. [std_any](std_any.md) | `std::any` с `volatile` |

`volatile`-контейнер отвергается на вызове, а не приводит к ошибке внутри библиотеки:
контейнер держит объект внутри себя, поэтому его волатильность доходит до объекта, а
методов доступа с квалификатором `volatile` у контейнера нет. `std::any` с квалификатором
`volatile` отвергается так же: `std::any_cast` не принимает указателя на такой объект. С
представлением наоборот - его собственная квалификация управляет только представлением и в
запросе не участвует, поэтому для `volatile`-представления над неквалифицированным объектом
приведение `any_cast<T>` возвращает значение.

### Как присоединиться

Тип присоединяется специализацией `scl::any_cast_traits` в пространстве имён `scl`.
Специализация несёт одно имя:

```cpp
struct boxed_int
{
    int value;
};

namespace scl
{
    template <>
    struct any_cast_traits<boxed_int>
    {
        template <typename Target, typename Source>
        static constexpr auto access(Source * box) noexcept
            -> decltype(std::addressof(box->value))
        {
            return std::addressof(box->value);
        }
    };
} // namespace scl
```

Метод `access<Target, Source>` возвращает адрес объекта либо `nullptr`, если запрос не
выполнен. Нулевым указатель `Source` там не бывает: функция `scl::any_cast` проверяет это один
раз и в противном случае ничего не вызывает, поэтому специализация своего случая для нуля не
описывает. Специализация пересылает работу самому источнику и собственного алгоритма не
содержит.

Тип результата `access` и есть тип результата приведения, и правило доступа записано именно
им: источник, не отдающий запись, возвращает `Target const *`, отдающий - `Target *`, а тот,
чья собственная константность доходит до объекта, переносит её в тип результата. Тип, на
который указывает результат, сверяется с написанием с точностью до квалификаторов, поэтому
специализация, возвращающая указатель на базовый класс того, что хранит её источник,
требование не выполняет, и для такого написания приведение не объявляется.

Специализация может объявить ещё одно имя - тип `movable_tag`, определять который не нужно.
Объявление говорит, что источник владеет тем, что отдаёт, поэтому такой источник без имени в
точке вызова читается перемещением объекта наружу; специализация, оставившая имя без
объявления, читается копированием.

```cpp
namespace scl
{
    template <>
    struct any_cast_traits<boxed_int>
    {
        struct movable_tag;

        template <typename Target, typename Source>
        static constexpr auto access(Source * box) noexcept
            -> decltype(std::addressof(box->value))
        {
            return std::addressof(box->value);
        }
    };
} // namespace scl
```

Функция `scl::any_cast` объявлена ровно там, где компилируется вызов, который она пересылает,
и где этот вызов возвращает такой указатель, поэтому для источника, который такое значение
вернуть не может, никакого отдельного условия писать не нужно. Если методы, которые вызывает
`access`, для такого `Source` вызвать нельзя, либо `Target` такой `access` выдать не может,
требование `requires` не выполняется, и вызывающая сторона читает, что такого приведения нет.
Спецификация `noexcept` формы с указателем следует из того, бросает ли `access`.

Для объявления открывают `namespace scl`. Квалифицированное имя в охватывающей области
(`template <> struct scl::any_cast_traits<boxed_int>`) корректно начиная с C++17, и его
принимают оба компилятора, а вот запись с ведущим `::`
(`struct ::scl::any_cast_traits<...>`) GCC отвергает.

Метод `access` вызывает `scl::any_cast`, а не пользователь: прямой вызов пропускает проверку
на нулевой указатель. Специализировать трейт для типа, который библиотека обслуживает сама,
не следует: такая специализация подменяет собственную реализацию библиотеки для этого типа.

Для типа без специализации приведения нет вовсе, и вызывающей стороне сообщают об этом на
вызове, а не показывают ошибку внутри приведения. Квалификация самого источника в этом не
участвует: константное и `volatile`-представление приводимы ровно тогда, когда приводимо
представление без квалификаторов, потому что собственная квалификация представления управляет
им самим, а не объектом, на который оно ссылается.

Объявлено ли приведение - это ограничение, и компилятор запоминает его вычисленное значение
для каждого источника, поэтому специализация обязана быть видна до первой проверки для её
типа. Достаточно подключить заголовок, определяющий источник, прежде чем проверять; проверить
сначала и подключить потом - некорректная программа, о которой компилятор сообщать не обязан.
Подключение `<scl/utility/any.h>` сразу называет все источники, которым служит библиотека.
