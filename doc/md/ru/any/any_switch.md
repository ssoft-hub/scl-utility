# Any switch

Цепочка ветвей: выполняет одну ветвь, выбранную по фактическому типу значения.

- Заголовок: `#include <scl/utility/any/any_switch.h>`

## Обзор

Чтобы прочитать разнородное значение, тип которого известен только во время
выполнения, до сих пор приходилось выстраивать череду проб
[`scl::any_cast`](any_view.md): по вызову на каждый возможный тип, у
каждого свой `if`, а поведение «ни один не подошёл» дописывалось отдельно. Тип при
этом упоминается в ветви дважды — в самом приведении и в переменной, которую оно
заполняет, — и ничто не мешает двум ветвям перекрыть друг друга или не сработать
никогда.

`scl::any_switch` сводит всё это к одному выражению. Тип в ветви указывается один
раз, срабатывает первая подходящая ветвь, а запасная стоит в той же цепочке.
Читать можно всё, что принимает [`scl::any_arg`](any_arg.md): типизированное lvalue
или rvalue, [`scl::any_view`](any_view.md), а в сборке с RTTI — и `std::any`.

Само значение цепочка не хранит. `in_case` и `or_else` лишь описывают ветви;
выполняет их `apply` над тем значением, которое ему передали, а `has_case` отвечает,
есть ли что выполнять. Поэтому одна цепочка обслуживает сколько угодно значений, ни
одно из них не обязано жить дольше неё, а сама цепочка — обычный объект: её можно
положить в переменную, поле или контейнер, вернуть из функции и применять там, где
значение появится.

```cpp
constexpr auto matcher = scl::any_switch<std::string>()
    .in_case<void>("значения нет")
    .in_case<int>([](int number) { return std::to_string(number); })
    .in_case<std::string const &>([](std::string const & text) { return text; })
    .or_else("неизвестно");

std::optional<std::string> result = matcher.apply(value);   // без предварительных проверок
bool covered = matcher.has_case(value);                     // ветвь не выполняется
```

## Возможности

- Одна цепочка на сколько угодно значений; по времени жизни ни с чем не связана
- Ветвь выбирается по тому же правилу покрытия квалификаторов, что и у `any_cast`,
  включая `volatile`
- `in_case<void>` — для пустого значения; `std::any` разворачивается автоматически
- Ветвь задаётся вызываемым объектом — без аргументов или принимающим найденное
  значение; при именованном `Result` — ещё и готовым значением
- Необязательная запасная ветвь `or_else`, получающая значение как `any_arg`
- `has_case` только выбирает ветвь: ничего не выполняется, побочных эффектов нет,
  метод `noexcept`
- Ветвь, покрытая предыдущей, второй `or_else` и `in_case` после него не компилируются
- Всё доступно на этапе компиляции, начиная с C++20

## Справочник по API

### Начало цепочки

```cpp
scl::any_switch<>();               // apply не возвращает ничего
scl::any_switch<std::string>();    // apply возвращает std::optional<std::string>
```

По умолчанию `Result` — `void`. Именованный `Result` должен быть объектным типом:
`apply` отдаёт его в `std::optional<Result>` — пустом, если не подошла ни одна ветвь,
и равно если подошедшая ветвь не дала результата.

### Ветви

```cpp
auto matcher = scl::any_switch<>()
    .in_case<void>([]() { /* значения нет */ })
    .in_case<int>([](int number) { /* копия */ })
    .in_case<std::string const &>([](std::string const & text) { /* без копирования */ })
    .in_case<double &>([](double & ratio) { ratio *= 2; })
    .in_case<char>();              // подходит и ничего не делает
```

Ветвь задаётся типом, и это либо объектный тип, либо lvalue-ссылка на него, либо
`void`. Rvalue-ссылка не принимается — по той же причине, что и у представления:
ничто здесь не должно выглядеть перемещаемым.

`in_case<Type>()` без аргумента — ветвь, которая подходит и ничего не делает. Так тип
забирают у запасной ветви, не сочиняя для него пустую лямбду. Форма имеет смысл
только при `Result = void`, где «ничего» и есть готовый результат; для именованного
`Result` это ошибка компиляции.

Вслед за типом `in_case` принимает вызываемый объект — без аргументов или с одним,
который конструируется из типа ветви. При именованном `Result` принимается и готовое
значение; в цепочке с `Result = void` преобразовывать его не во что, поэтому там это
ошибка компиляции, а «подойти и ничего не сделать» записывается как `in_case<Type>()`:

```cpp
auto named = scl::any_switch<std::string>()
    .in_case<int>("целое")                                // значение
    .in_case<double>([]() { return "вещественное"; })     // без аргумента
    .in_case<char>([](char symbol) { return std::string(1, symbol); });
```

Вызываемый объект получает найденное значение, если принимает аргумент, и вызывается
пустым, если не принимает: `[](char symbol) { ... }` значение получает, `[]() { ... }` —
нет. Если компилируются оба вызова, передаётся найденное значение.

Дать ветвь может как сам `Result`, так и `std::optional<Result>` с ним внутри — это
касается обеих форм, и вызываемого объекта, и готового значения. Пустой `optional`
означает, что ветвь сработала, но результата не дала:

```cpp
auto parsed = scl::any_switch<std::string>()
    .in_case<int>([](int value) -> std::optional<std::string> {
        return value > 0 ? std::optional{std::to_string(value)} : std::nullopt;
    })
    .in_case<char>(std::optional<std::string>{});   // готовое значение, тоже optional
```

### Вложенные цепочки

Именно вторая форма позволяет собирать цепочки друг из друга. Цепочка — вызываемый
объект, возвращающий `std::optional<Result>`, а значит, годится ветвью внешней
цепочки, в том числе запасной:

```cpp
auto const inner = scl::any_switch<std::string>().in_case<double>("вещественное");
auto const outer = scl::any_switch<std::string>().in_case<int>("целое").or_else(inner);

outer.apply(number);   // "целое"        — сработала ветвь внешней цепочки
outer.apply(ratio);    // "вещественное" — управление ушло во вложенную
outer.apply(symbol);   // пусто          — не подошло ни там, ни там
```

Значение, к которому не подошла ни одна ветвь, даёт пустой результат, а не неверный.
Учтите: `has_case` отвечает только за ту цепочку, которой задан вопрос, и внутрь
вложенной не заглядывает — запасная ветвь покрывает любое значение, что бы ни решила
цепочка за ней.

### Как выбирается ветвь

Правило покрытия квалификаторов взято у `any_cast` и воспроизведено целиком:

| Ветвь | Когда подходит |
|---|---|
| `in_case<T>` | объект типа `T` или `T const`; будет ли копия, решает параметр самой ветви |
| `in_case<T const &>` | те же объекты, но без копирования |
| `in_case<T &>` | только объект без квалификаторов, с доступом к объекту вызывающей стороны |
| `in_case<T volatile &>` | объект без квалификаторов или с `volatile`; этот квалификатор покрывает так же, как `const` |
| `in_case<void>` | пустое значение |

`in_case<std::any>` не подходит к самому `std::any` — ровно как и
`any_cast<std::any>`: объект внутри разворачивается, и ветви видят его тип.

Ветвь, которую целиком покрывает какая-то из предыдущих, — ошибка компиляции, а не
ветвь, которая никогда не сработает. Покрытие при этом считается по тому, что ветвь
ловит, а не по тому, как она записана: `in_case<T>` и `in_case<T const &>` берут одни и
те же объекты, поэтому вторая после первой отвергается; обе берут и всё, что берёт
`in_case<T &>`, поэтому он отвергается после любой из них.

Решает порядок. Записанный первым, `in_case<T &>` оставляет за собой объект без
квалификаторов, а идущий следом `in_case<T const &>` по-прежнему забирает объекты с
`const`:

```cpp
auto matcher = scl::any_switch<>()
    .in_case<int &>([](int & number) { number *= 2; })     // объект без квалификаторов
    .in_case<int const &>([](int const &) { /* ... */ });  // объекты с const, ещё свободны
```

### Запасная ветвь

```cpp
auto matcher = scl::any_switch<std::string>()
    .in_case<int>("целое")
    .or_else([](scl::any_arg other) { return std::string{other.type_name()}; });
```

`or_else` необязательна и принимает всё, к чему не подошла ни одна ветвь, — в том
числе пустое значение, если в цепочке нет `in_case<void>`. Это такая же ветвь, как
остальные: она возвращает цепочку, а не результат. Раз она принимает всё, ставить
что-либо после неё и повторять её нельзя — и то и другое ошибка компиляции.

### Применение

```cpp
std::optional<std::string> result = matcher.apply(value);
```

`apply` берёт первую подходящую ветвь в порядке записи, выполняет только её и
возвращает `std::optional<Result>` — пустой, если не подошла ни одна. Цепочка с
`Result = void` не возвращает ничего, и при отсутствии подходящей ветви просто ничего
не делает.

Вызывать `apply` можно сколько угодно раз и для скольких угодно значений: цепочка
описывает ветви и не хранит результат, поэтому ветвь с побочным эффектом
срабатывает при каждом вызове. Предварительных проверок не требуется — отсутствие
подходящей ветви — это обычный исход, о котором сообщает результат.

`apply` помечен `noexcept`, когда `noexcept` все ветви, которые он может выполнить, и
перемещение результата не бросает. Форма `const` доступна там, где эти ветви вызываются
на константной цепочке;
цепочка с `mutable`-объектом внутри ветви применяется через неконстантную.

`operator()` делает ровно то же самое: тот же выбор ветви, тот же результат, те же
формы `const` и `noexcept`:

```cpp
matcher(value);                                  // то же, что matcher.apply(value)
std::ranges::transform(values, out, matcher);    // цепочка — вызываемый объект
```

Он избавляет от лямбды-обёртки там, где нужен вызываемый объект. Это именно вызов, а
не преобразование: цепочка по-прежнему ни во что не преобразуется.

### Проверка без выполнения

```cpp
if (matcher.has_case(value))
    matcher.apply(value);          // ветвь дорогая или с побочным эффектом
```

`has_case` сообщает, подходит ли значению хоть одна ветвь. Он доходит до выбора ветви
и останавливается: ветвь не выполняется, побочных эффектов нет, метод `noexcept`.
Если в цепочке есть `or_else`, ответ всегда положительный.

| Состояние | `has_case(value)` | `apply(value)`, именованный `Result` | `apply(value)`, `Result = void` |
|---|---|---|---|
| ни одна ветвь не подошла | `false` | пусто | ничего не выполняется |
| ветвь подошла | `true` | её значение, пусто — если не дала результата | выполняется эта ветвь |

То есть по пустому результату строки не различить — на вопрос «подошла ли хоть одна
ветвь» отвечает `has_case`.

Неявного преобразования цепочки к результату, к `bool` или к чему-либо ещё нет:
цепочка — это описание, и получение результата записывается явным вызовом.

### Что откладывается, а что нет

Построение цепочки не выполняет ничего: ни выбора ветви, ни её самой, ни
результата. Единственное, что отложить нельзя, — ветвь, заданную готовым *значением*:
`or_else(compute())` вычислит `compute()` там, где это написано, ведь это обычный
аргумент функции. Если построение значения дорого, передавайте вызываемый объект.

## Вычисление на этапе компиляции

Цепочка остаётся литеральным типом, пока литеральны её ветви, а значение
попадает в `apply` параметром — то есть туда, где приведение
[`any_arg`](any_arg.md#вычисление-на-этапе-компиляции) вычисляется на этапе
компиляции уже в C++20. Поэтому `constexpr`-цепочка, применённая в константном
выражении, выбирает и выполняет ветвь при компиляции, причём без ограничений, которые
накладывает хранимый `any_arg`:

```cpp
constexpr auto doubling = scl::any_switch<int>()
    .in_case<int>([](int number) { return number * 2; })
    .or_else(0);

static_assert(doubling.apply(21).value() == 42);
static_assert(doubling.has_case(21));
```

## Исключения

Цепочка ничего не перехватывает и ни во что не заворачивает. Исключение из ветви
выходит из `apply` в кадре вызывающей стороны и ловится обычным `try` вокруг этого
вызова. Повиснуть может только ветвь, захватившая что-то по ссылке, — и повисает она
так же, как любая захваченная ссылка.
