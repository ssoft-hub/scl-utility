# Any switch

`scl::any_switch` описывает набор ветвей, каждая из которых отвечает за свой тип, и
выполняет ту из них, которая подходит фактическому типу переданного значения.

- Заголовок: `#include <scl/utility/any/any_switch.h>`

## Обзор

Чтобы прочитать значение, тип которого известен только во время выполнения, до сих пор
приходилось выстраивать череду проб [`scl::any_cast`](any_view.md): по вызову на каждый
возможный тип, у каждого свой `if`, а поведение для случая «ни один тип не подошёл»
дописывалось отдельно. Тип при этом упоминается в ветви дважды - в самом приведении и в
переменной, которую оно заполняет, - и ничто не мешает двум ветвям перекрыть друг друга
или не сработать никогда.

`scl::any_switch` сводит это к одному выражению. Тип в ветви называется один раз,
срабатывает первая подходящая ветвь, а запасная стоит в той же цепочке. Читать цепочка
может всё, что принимает [`scl::any_arg`](any_arg.md): именованный или временный объект
известного типа, [`scl::any_view`](any_view.md), а в сборке с RTTI -
и `std::any`.

Само значение цепочка не хранит. Методы `in_case` и `or_else` только описывают ветви.
Выполняет их `apply` над тем значением, которое ему передали, а `has_case` отвечает, есть
ли что выполнять. Поэтому одна цепочка обслуживает сколько угодно значений, ни одно из них
не обязано жить дольше неё, а сама цепочка ведёт себя как обычный объект: её можно
положить в переменную, поле или контейнер, вернуть из функции и применить там, где значение
появится.

```cpp
constexpr auto matcher = scl::any_switch<std::string>()
    .in_case<void>("значения нет")
    .in_case<int>([](int number) { return std::to_string(number); })
    .in_case<std::string const &>([](std::string const & text) { return text; })
    .or_else("неизвестно");

std::optional<std::string> result = matcher.apply(value);   // без предварительных проверок
bool covered = matcher.has_case(value);                     // ветвь не выполняется
```

## Возможности

- Обслуживает сколько угодно значений и не связана временем жизни ни с одним из них.
- Выбирает ветвь по тому же правилу покрытия квалификаторов, что и `any_cast`, включая
  `volatile`.
- Принимает ветвь `in_case<void>` для пустого значения и разворачивает `std::any`
  автоматически.
- Позволяет задать ветвь вызываемым объектом - без аргументов или принимающим найденное
  значение, - а при именованном типе результата ещё и готовым значением.
- Принимает необязательную запасную ветвь `or_else`, которая получает значение как
  `any_arg`.
- Отвечает `has_case`, не выполняя ветвь: побочных эффектов нет, метод объявлен `noexcept`.
- Отвергает при компиляции ветвь, полностью покрытую предыдущей, вторую `or_else` и любую
  ветвь после неё.
- Работает на этапе компиляции, начиная с C++20.

## Справочник по API

### Начало цепочки

```cpp
scl::any_switch<>();               // apply ничего не возвращает
scl::any_switch<std::string>();    // apply возвращает std::optional<std::string>
```

Параметр `Result` по умолчанию равен `void`. Если его назвать явно, он должен быть
объектным типом: тогда `apply` возвращает `std::optional<Result>`. Результат пуст, если не
подошла ни одна ветвь, и точно так же пуст, если подошедшая ветвь не выдала значения.

### Ветви

```cpp
auto matcher = scl::any_switch<>()
    .in_case<void>([]() { /* значения нет */ })
    .in_case<int>([](int number) { /* копия значения */ })
    .in_case<std::string const &>([](std::string const & text) { /* без копирования */ })
    .in_case<double &>([](double & ratio) { ratio *= 2; })
    .in_case<char>();              // ветвь подходит и ничего не делает
```

Ветвь задаётся типом. Это либо объектный тип, либо lvalue-ссылка на него, либо `void`.
Ссылка на временный объект не принимается по той же причине, что и у представления: ничто
здесь не должно выглядеть перемещаемым.

Вызов `in_case<Type>()` без аргумента описывает ветвь, которая подходит и ничего не делает.
Так тип забирают у запасной ветви, не сочиняя для него пустую лямбду. Эта форма имеет смысл
только при `Result = void`, где «ничего» и есть готовый результат. При именованном
результате она не компилируется.

Вслед за типом `in_case` принимает вызываемый объект - без аргументов или с одним
аргументом, который конструируется из типа ветви. При именованном результате принимается и
готовое значение. В цепочке с `Result = void` преобразовывать такое значение не во что,
поэтому там оно не компилируется, а ветвь «подойти и ничего не сделать» записывается как
`in_case<Type>()`:

```cpp
auto named = scl::any_switch<std::string>()
    .in_case<int>("целое")                                // готовое значение
    .in_case<double>([]() { return "вещественное"; })     // вызываемый объект без аргумента
    .in_case<char>([](char symbol) { return std::string(1, symbol); });
```

Вызываемый объект получает найденное значение, если принимает аргумент, и вызывается без
аргументов, если не принимает. Лямбда `[](char symbol) { ... }` значение получит, лямбда
`[]() { ... }` - нет. Если компилируются оба вызова, цепочка передаёт найденное значение.

Ветвь может выдать как сам `Result`, так и `std::optional<Result>`. Это касается обеих
форм - и вызываемого объекта, и готового значения. Пустой `optional` означает, что ветвь
сработала, но результата не дала:

```cpp
auto parsed = scl::any_switch<std::string>()
    .in_case<int>([](int value) -> std::optional<std::string> {
        return value > 0 ? std::optional{std::to_string(value)} : std::nullopt;
    })
    .in_case<char>(std::optional<std::string>{});   // готовое значение, тоже optional
```

### Вложенные цепочки

Именно вторая форма позволяет собирать цепочки друг из друга. Цепочка сама является
вызываемым объектом и возвращает `std::optional<Result>`, поэтому годится ветвью другой
цепочки, в том числе запасной:

```cpp
auto const inner = scl::any_switch<std::string>().in_case<double>("вещественное");
auto const outer = scl::any_switch<std::string>().in_case<int>("целое").or_else(inner);

outer.apply(number);   // "целое": сработала ветвь внешней цепочки
outer.apply(ratio);    // "вещественное": управление ушло во вложенную цепочку
outer.apply(symbol);   // пусто: не подошло ни там, ни там
```

Значение, к которому не подошла ни одна ветвь, даёт пустой результат, а не неверный.
Учтите, что `has_case` отвечает только за ту цепочку, которой задан вопрос, и внутрь
вложенной не заглядывает: запасная ветвь покрывает любое значение, что бы ни решила
цепочка за ней.

### Как выбирается ветвь

Правило покрытия квалификаторов взято у `any_cast` и воспроизведено целиком:

| Ветвь | Когда подходит |
|---|---|
| `in_case<T>` | объект типа `T` или `T const`; будет ли копия, решает параметр самой ветви |
| `in_case<T const &>` | те же объекты, но без копирования |
| `in_case<T &>` | только объект без квалификаторов, с доступом к объекту вызывающей стороны |
| `in_case<T volatile &>` | объект без квалификаторов или с `volatile`; этот квалификатор покрывает так же, как `const` |
| `in_case<void>` | пустое значение |

Ветвь `in_case<std::any>` не подходит самому `std::any` - ровно как и
`any_cast<std::any>`: объект внутри разворачивается, и ветви видят его тип.

Ветвь, которую целиком покрывает какая-то из предыдущих, не компилируется. Так цепочка не
позволяет написать ветвь, которая никогда не сработает. Покрытие считается по тому, какие
объекты ветвь ловит, а не по тому, как она записана. Формы `in_case<T>` и
`in_case<T const &>` берут одни и те же объекты, поэтому вторая после первой отвергается.
Обе берут и всё, что берёт `in_case<T &>`, поэтому он отвергается после любой из них.

Решает порядок записи. Если `in_case<T &>` записан первым, он оставляет за собой объект без
квалификаторов, а идущий следом `in_case<T const &>` по-прежнему забирает объекты с
`const`:

```cpp
auto matcher = scl::any_switch<>()
    .in_case<int &>([](int & number) { number *= 2; })     // объект без квалификаторов
    .in_case<int const &>([](int const &) { /* ... */ });  // объекты с const, ещё свободны
```

### Запасная ветвь

```cpp
auto matcher = scl::any_switch<std::string>()
    .in_case<int>("целое")
    .or_else([](scl::any_arg other) { return std::string{other.type_name()}; });
```

Метод `or_else` необязателен и принимает всё, к чему не подошла ни одна ветвь, в том числе
пустое значение, если в цепочке нет ветви `in_case<void>`. Это такая же ветвь, как
остальные: она возвращает цепочку, а не результат. Поскольку она принимает всё, ставить
что-либо после неё и повторять её нельзя - и то и другое не компилируется.

### Применение

```cpp
std::optional<std::string> result = matcher.apply(value);
```

Метод `apply` берёт первую подходящую ветвь в порядке записи, выполняет только её и
возвращает `std::optional<Result>`. Результат пуст, если не подошла ни одна ветвь. Цепочка
с `Result = void` ничего не возвращает и при отсутствии подходящей ветви просто ничего не
делает.

Вызывать `apply` можно сколько угодно раз и для скольких угодно значений: цепочка описывает
ветви и не хранит результат, поэтому ветвь с побочным эффектом срабатывает при каждом
вызове. Предварительных проверок не требуется, ведь отсутствие подходящей ветви - это
обычный исход, о котором сообщает результат.

Метод `apply` объявлен `noexcept`, когда объявлены `noexcept` все ветви, которые он может
выполнить, и когда перемещение результата не выбрасывает исключений. Константная форма
доступна там, где эти ветви вызываются на константной цепочке. Цепочка, у которой в ветви
лежит объект с изменяемым состоянием, применяется через неконстантную форму.

Оператор `operator()` делает ровно то же самое: тот же выбор ветви, тот же результат, те же
формы `const` и `noexcept`:

```cpp
matcher(value);                                  // то же, что matcher.apply(value)
std::ranges::transform(values, out, matcher);    // цепочка сама является вызываемым объектом
```

Он избавляет от лямбды-обёртки там, где нужен вызываемый объект. Это именно вызов, а не
преобразование: сама цепочка ни во что не преобразуется.

### Проверка без выполнения

```cpp
if (matcher.has_case(value))
    matcher.apply(value);          // ветвь дорогая или с побочным эффектом
```

Метод `has_case` сообщает, подходит ли значению хоть одна ветвь. Он доходит до выбора ветви
и останавливается: ветвь не выполняется, побочных эффектов нет, метод объявлен `noexcept`.
Если в цепочке есть запасная ветвь, ответ всегда положительный.

| Состояние | `has_case(value)` | `apply(value)` при именованном `Result` | `apply(value)` при `Result = void` |
|---|---|---|---|
| ни одна ветвь не подошла | `false` | пусто | ничего не выполняется |
| ветвь подошла | `true` | её значение; пусто, если она не дала результата | выполняется эта ветвь |

По пустому результату две строки таблицы не различить, поэтому на вопрос «подошла ли хоть
одна ветвь» отвечает `has_case`.

Цепочка не преобразуется неявно ни к результату, ни к `bool`, ни к чему-либо ещё: она
описывает ветви, а получение результата записывается явным вызовом.

### Что откладывается, а что нет

Построение цепочки не выполняет ничего: ни выбора ветви, ни её самой, ни вычисления
результата. Единственное, что отложить нельзя, - это ветвь, заданную готовым **значением**.
Запись `or_else(compute())` вычислит `compute()` там, где она написана, ведь это обычный
аргумент функции. Если построение значения обходится дорого, передавайте вызываемый объект.

## Вычисление на этапе компиляции

Цепочка остаётся литеральным типом, пока литеральны её ветви. Значение попадает в `apply`
параметром, то есть туда, где приведение
[`any_arg`](any_arg.md#вычисление-на-этапе-компиляции) вычисляется на этапе компиляции уже
на C++20. Поэтому цепочка, объявленная `constexpr` и применённая в константном выражении,
выбирает и выполняет ветвь при компиляции, причём без ограничений, которые накладывает
`any_arg` в локальной переменной:

```cpp
constexpr auto doubling = scl::any_switch<int>()
    .in_case<int>([](int number) { return number * 2; })
    .or_else(0);

static_assert(doubling.apply(21).value() == 42);
static_assert(doubling.has_case(21));
```

## Исключения

Цепочка ничего не перехватывает и ни во что не заворачивает. Исключение, выброшенное
ветвью, выходит из `apply` в кадре вызывающей стороны, и его ловит обычный `try` вокруг
этого вызова. Недействительной может стать только ветвь, захватившая что-то по ссылке, - и
происходит это так же, как с любой захваченной ссылкой.
