# Any mutable view

`scl::any_mutable_view` описывает объект, который может ссылаться на изменяемое значение
любого типа. Тип значения не входит в тип представления, поэтому одна и та же функция
принимает значение любого типа; фактический тип сообщают `type_name()`, `type_key()` и
`scl::any_cast`. Представление читает и записывает значение: оно его не создаёт, не
копирует и не разрушает, а хранит его адрес вместе с описанием типа.

- Заголовок: `#include <scl/utility/any/any_mutable_view.h>`

## Обзор

`scl::any_mutable_view` - это [`scl::any_view`](any_view.md), дающий доступ на запись. Оба
представления можно хранить: положить в поле, в контейнер, вернуть из функции. Оба
занимают два указателя и копируются тривиально. Представление без уточнения только читает,
представление с `mutable` читает и записывает.

Группа Any различает представления по двум признакам: можно ли хранить представление и
даёт ли оно доступ на запись.

| представление | хранимое | доступ на запись | связывает временный объект |
|---|---|---|---|
| [`scl::any_view`](any_view.md) | да | нет | нет |
| [`scl::any_arg`](any_arg.md) | нет | да | да |
| `scl::any_mutable_view` | да | да | нет |

В терминах обычных ссылок это `T const &`, параметр и `T &`.

`scl::any_mutable_view` применяют, когда запись выполняется после вызова, в котором
представление было связано с объектом: значение приходит позже - из разбора аргументов
командной строки, из конфигурации, из сети - и записывается по сохранённому представлению.
[`scl::any_arg`](any_arg.md) для этого не годится: он действителен только в пределах
вызова.

Связывание уже, чем у [`scl::any_view`](any_view.md). Константный объект не связывается: он
не даёт доступа на запись. Временный объект не связывается независимо от константности:
представление хранимое и пережило бы его. Объект с `volatile` связывается, а приведение к
нему подчиняется правилу квалификаторов, описанному ниже.

Остальное совпадает с [`scl::any_view`](any_view.md): те же два способа сослаться на
объект - типизированный объект любого типа, включая `std::any`, который связывается как
обычный объект, - те же запросы идентичности и те же ограничения на вычисления во время
компиляции.

## Возможности

- Ссылается на объект, ничего не копируя, и даёт доступ на запись.
- Хранится: его можно положить в поле, в контейнер, вернуть из функции.
- Занимает два указателя и копируется тривиально.
- Отвергает константный объект и временный объект любой константности.
- Ссылается на типизированный объект любого типа и не использует RTTI.
- Ссылается на `std::any` и пишет сам этот объект - тем же конструктором, каким принимает
  любой другой тип.
- Ссылается на содержимое [`scl::any`](any.md), а не на сам контейнер.
- Отвечает на запросы `type_name()`, `type_key()` и `has_value()` в том числе на этапе
  компиляции, начиная с C++20.
- Отдаёт указатель через `any_cast<T>(view *)`; при несовпадении типа возвращается
  `nullptr`, исключение не выбрасывается.
- Отдаёт значение или ссылку через `any_cast<T>(view &)`; при несовпадении типа выбрасывает
  `scl::bad_any_cast`.
- Разрешает запись через `any_cast<T>(view *)` или `any_cast<T &>`; для объекта с
  `volatile` запрос обязан повторить этот квалификатор.
- Преобразуется в [`scl::any_view`](any_view.md) и в [`scl::any_arg`](any_arg.md); обратно
  не преобразуется ни то, ни другое.

## Справочник по API

### Построение

```cpp
std::string text{"Hello Any!"};
std::string const frozen{"read only"};

scl::any_mutable_view empty{};      // ни на что не ссылается
scl::any_mutable_view raw{text};    // ссылается на объект напрямую
scl::any_mutable_view alias = raw;  // копируется тривиально

scl::any_mutable_view refused{frozen};                 // не компилируется: объект константный
scl::any_mutable_view also_refused{std::string{"x"}};  // не компилируется: временный объект
```

Константный объект отвергается типом, а не приведением, поэтому отказ - ошибка компиляции в
месте связывания. Функция, которой достаточно чтения, объявляет параметр как
[`scl::any_view`](any_view.md): он связывает и константный объект, и неконстантный.

Неконстантный `std::any` преобразуется в представление неявно, как любое другое
неконстантное именованное значение:

```cpp
std::any boxed{text};
scl::any_mutable_view over_any{boxed};   // может писать сам std::any
```

Такое представление даёт доступ к самому `std::any` и больше ни к чему. `any_cast<std::any>`
возвращает этот объект, и запись через него заменяет всё, что тот хранит, а `any_cast<T>` с
типом хранимого значения возвращает `nullptr`. Чтобы изменить хранимый объект на месте,
возьмите сам `std::any` и передайте его `std::any_cast`:

```cpp
std::any_cast<std::string &>(*scl::any_cast<std::any>(&over_any)) += "!";
```

[`scl::any`](any.md) раскрывается до своего содержимого, как и для
[`scl::any_view`](any_view.md):

```cpp
scl::any owner{42};
scl::any_mutable_view over_owner{owner};   // ссылается на int, а не на сам any

over_owner.type_name();   // "int"
```

### Наблюдение

`has_value()`, `type_name()` и `type_key()` возвращают то же, что и у
[`scl::any_view`](any_view.md). Для `std::any` идентичность называет сам контейнер, а не
тип, лежащий внутри него.

### Приведение

Указательная форма возвращает запрошенный тип: `any_cast<T>` запрашивает запись,
`any_cast<T const>` - чтение. При совпадении типа запрос разрешается. Отказать может только
квалификатор `volatile` у объекта: его запрос обязан повторить. Константности среди
квалификаторов объекта не бывает, потому что константный объект не связывается.

```cpp
int number = 7;
scl::any_mutable_view const view{number};

int *       w = scl::any_cast<int>(&view);       // запись доходит до number
int const * r = scl::any_cast<int const>(&view); // чтение того же объекта
scl::any_cast<long>(&view);                      // nullptr: другой тип
```

Ссылочная форма выражает тот же выбор ссылочным типом: `any_cast<T &>` пишет,
`any_cast<T const &>` читает, `any_cast<T>` копирует значение наружу. При несовпадении типа
она выбрасывает `scl::bad_any_cast` и объявлена только там, где
[`SCL_HAS_EXCEPTIONS`](../preprocessor/exceptions.md) равен `1`.

### Константность самого представления

Константное представление запрещает перепривязку, а не запись:

<!-- snippet: example/any/mutable_view/any_mutable_view_example.cpp const_view_writes -->
```cpp
static void bump(::scl::any_mutable_view const & view)
{
    if (auto * const number = ::scl::any_cast<int>(&view))
        ++*number;
    else
        ::std::cout << "  refused: the referent is not a writable int\n";
}
```

Правило общее для всей группы: собственные квалификаторы представления относятся к нему
самому, а с запросом сверяются только квалификаторы объекта. Поэтому
`volatile`-представление пишет в неквалифицированный объект, ничего не требуя от запроса.
Функция, которой запись не нужна, объявляет параметр как `scl::any_view`.

### Квалификаторы const и volatile у объекта

Представление помнит квалификаторы объекта, с которым его связали, и приведение обязано
запросить их все. Константности среди них быть не может, потому что константный объект не
связывается, поэтому запрашивать приходится только `volatile`:

```cpp
int volatile sensor = 0;
scl::any_mutable_view const view{sensor};

scl::any_cast<int>(&view);           // nullptr: запрос отбросил бы volatile
scl::any_cast<int volatile>(&view);  // int volatile *, и через него можно писать
```

### Преобразования

Представление преобразуется в оба читающих типа группы, обратных преобразований нет:

```cpp
int number = 7;
scl::any_mutable_view const view{number};

scl::any_view reading = view;   // сужено до чтения, тот же объект
takes_an_argument(view);        // scl::any_arg: сохраняет запись на время вызова
```

Сужение до [`scl::any_view`](any_view.md) снимает доступ на запись, и восстановить его из
полученного представления нечем. Преобразование в [`scl::any_arg`](any_arg.md) доступ
сохраняет: аргумент заявляет тот же контракт на время вызова. Обратного преобразования нет
ни у одного из двух: представление, которое записи не обещает, её не получает.

Цепочка [`scl::any_switch`](any_switch.md) принимает такое представление как значение, а
ветвь, записанная как `in_case<T &>`, добирается до объекта вызывающей стороны:

```cpp
int number = 41;
scl::any_mutable_view const view{number};

scl::any_switch<>().in_case<int &>([](int & reached) { ++reached; }).apply(view);
// number == 42
```

[`scl::any`](any.md), построенный или присвоенный из такого представления, хранит копию
объекта, на который представление ссылается, а не само представление.

### Хранение представления

Представление можно сохранить и воспользоваться им позже:

<!-- snippet: example/any/mutable_view/any_mutable_view_example.cpp stored_write -->
```cpp
class binder
{
public:
    template <typename Type>
    void bind(::std::string name, Type & slot)
    {
        m_slots.insert_or_assign(::std::move(name), ::scl::any_mutable_view{slot});
    }

    template <typename Type>
    bool fill(::std::string const & name, Type value) const
    {
        auto const found = m_slots.find(name);
        if (found == m_slots.end())
            return false;

        auto * const target = ::scl::any_cast<Type>(&found->second);
        if (target == nullptr)
            return false;

        *target = ::std::move(value);
        return true;
    }

private:
    ::std::unordered_map<::std::string, ::scl::any_mutable_view> m_slots;
};
```

Представление не хранит объект у себя и не продлевает его жизнь, поэтому каждый связанный
объект обязан пережить того, кто хранит представление. Запись по недействительному
представлению повреждает чужую память, тогда как чтение возвращает из неё мусор.

### Вычисления во время компиляции

Правила те же, что у [`scl::any_view`](any_view.md). Запросы идентичности вычисляются
начиная с C++20. Приведение вычисляется там, где библиотека может получить типизированный
указатель: над объектом во владении [`scl::any`](any.md), который лежит внутри контейнера,
либо через [`scl::any_anchor`](any_anchor.md), объявленный рядом с обычным объектом:

```cpp
constexpr int incremented()
{
    int value = 41;
    scl::any_anchor const anchor{value};
    scl::any_mutable_view const view{anchor};

    ++*scl::any_cast<int>(&view);
    return value;
}

static_assert(incremented() == 42);
```

Якорь, который [`scl::any_arg`](any_arg.md) создаёт сам, - временный объект вызывающей
стороны, существующий только на время вызова, поэтому хранимому представлению он не
подходит. Начиная с C++26 якорь не нужен: восстановление типизированного указателя из
`void const *` вычисляется там на этапе компиляции, и приведение сворачивается над любым
обычным объектом. Над `std::any` оно не сворачивается ни при каком стандарте: у самого
`std::any` нет операций, вычисляемых на этапе компиляции.
