# Ключ идентичности типа

Идентичность типа без RTTI, различающая одноимённые типы из анонимных пространств имён разных
единиц трансляции.

- Заголовок: `#include <scl/utility/meta/type_key.h>`

Содержание:
- [`type_key`](#type_key)
- [`type_key_of<T>`](#type_key_of)
- [`is_tu_local<T>`](#is_tu_local)

---

## type_key

`scl::type_key` идентифицирует один тип. Два ключа сравниваются на равенство и равны тогда,
когда идентифицируют один и тот же тип. Внутри ключ хранит имя типа, полученное на этапе
компиляции, и дискриминатор единицы трансляции.

- Заголовок: `#include <scl/utility/meta/type_key.h>`
- Объявление:

```cpp
class type_key
{
public:
    constexpr type_key() = default;
    constexpr type_key(type_key const &) = default;
    constexpr type_key(type_key &&) = default;
    constexpr type_key & operator=(type_key const &) = default;
    constexpr type_key & operator=(type_key &&) = default;
    constexpr ~type_key() = default;

    constexpr std::string_view name() const noexcept;

    friend constexpr bool operator==(type_key const &, type_key const &) noexcept;
    // != синтезируется из ==
};
```

### Семантика

Метод `name()` возвращает имя идентифицируемого типа в виде строки - ту самую, которую даёт
[`type_name<T>()`](type_name.md).

Дискриминатор наружу не выдаётся. Для типа с внешним связыванием он равен `nullptr`. Для типа
из анонимного пространства имён он хранит адрес объекта-якоря, отдельного у каждой единицы
трансляции, поэтому одноимённые типы из разных единиц трансляции получают разные
дискриминаторы.

Сравнение начинается с адресов. Функция `type_key_of<T>()` возвращает ссылку на константу,
отдельную у каждого типа, поэтому сравнение двух таких ссылок стоит одного сравнения
указателей. Если адреса различаются, сравниваются имя и дискриминатор.

Для типа, объявленного в пространстве имён, такое сравнение не даёт ни ложного совпадения, ни
ложного отказа. Одноимённые типы из анонимных пространств имён различаются дискриминатором.
Внешний тип, использованный и в исполняемом файле, и в разделяемой библиотеке, сравнивается по
имени при нулевом дискриминаторе с обеих сторон, поэтому неслитые inline-инстанцирования на
Windows равенство не нарушают.

Ключ, идентифицирующий тип, выдаёт только `type_key_of<T>()`. Собрать ключ вручную, подставив
имя одного типа и дискриминатор другого, невозможно: поля закрытые, а методов, изменяющих ключ,
нет. Написать самостоятельно можно единственный ключ - пустой `scl::type_key{}`. Он не
идентифицирует никакого типа и не равен ни одному ключу из `type_key_of`.

Ключ - значение: копируется, перемещается и присваивается. Копия идентифицирует тот же тип, что
и её источник, и равна ему.

Порядка у ключей нет: ни `operator<=>`, ни `std::less`. Идентичность опирается на адреса
объектов, а их взаимный порядок для несвязанных объектов стандарт не определяет, и в
константных выражениях он недоступен. Готовой хеш-функции тоже нет: как написать свою и
положить ключ в неупорядоченный контейнер, показывает пример в конце страницы.

### Время жизни ключа

Ключ указывает внутрь модуля - исполняемого файла или разделяемой библиотеки, - который его
создал: `name()` ссылается на строковый литерал этого модуля, дискриминатор - на его якорь.
Поэтому **ключ не должен пережить создавший его модуль**. После `FreeLibrary` или `dlclose` оба
указателя повисают, а модуль, загруженный затем по тому же базовому адресу, способен сделать
устаревший ключ ложно равным свежему и никак не связанному с ним. Удалите сохранённые ключи
прежде, чем выгружать модуль, который их создал.

## type_key_of<T>

Возвращает ссылку на `type_key`, идентифицирующий `T`.

- Заголовок: `#include <scl/utility/meta/type_key.h>`
- Объявление: `template <typename T> constexpr type_key const & type_key_of() noexcept;`

Ключ хранится в переменной `inline constexpr`, отдельной у каждого типа. Внутри одного модуля
все вызовы `type_key_of<T>()` для внешнего `T` обращаются к одному объекту, поэтому сравнение с
сохранённой ссылкой стоит одного сравнения адресов. Хранить ключ долго - например, в обёртке со
стиранием типа - можно и по ссылке, что сохраняет этот быстрый путь, и по значению; копия
сравнивается по содержимому.

### Предусловие

`T` должен быть объявлен в пространстве имён. Локальные классы и типы замыканий остаются вне
контракта: компилятор пишет их имя без надёжного признака локальности, и проверить это при
компиляции нечем. Clang пишет локальный класс одним именем, поэтому его ключ совпадает байт в
байт с ключом одноимённого типа из пространства имён, и два разных типа оказываются равны:

```cpp
struct duck {};                     // объявлен в пространстве имён
int main() {
    struct duck {};                 // локальный класс - вне контракта
    // проходит на Clang: ложное совпадение с обычным внешним типом
    static_assert(scl::type_key_of<::duck>() == scl::type_key_of<duck>());
}
```

GCC пишет `main()::duck`, MSVC - `struct main::duck`, и эти имена не совпадают. Чтобы такой тип
получил верный ключ, перенесите его в анонимное пространство имён той же единицы трансляции:

```cpp
namespace { struct duck {}; }             // верный ключ
```

### Примеры

```cpp
#include <scl/utility/meta/type_key.h>

namespace { struct duck {}; }
struct goose {};

constexpr auto & anon_key = scl::type_key_of<duck>();
constexpr auto & ext_key  = scl::type_key_of<goose>();

static_assert(anon_key == scl::type_key_of<duck>());
static_assert(anon_key != ext_key);
static_assert(&scl::type_key_of<goose>() == &ext_key);  // один объект на тип
```

Одноимённые типы из анонимных пространств имён разных единиц трансляции дают ключи с равными
именами и разными дискриминаторами, поэтому такие ключи не равны. Это и нужно механизму
стирания типа: прежде чем приводить стёртый указатель обратно к типу, он сравнивает сохранённый
ключ с ключом запрошенного типа.

### Типичные сценарии

Хранилища со стиранием типа - контейнеры в духе `any`, представления аргументов функции, -
которым нужно восстановить типизированный указатель по сохранённому ключу. RTTI при этом не
требуется, а сравнение одних только имён, которое ошиблось бы на одноимённых типах из разных
анонимных пространств, здесь не применяется.

## is_tu_local<T>

Отвечает, локален ли `T` для текущей единицы трансляции, то есть объявлен ли он в анонимном
пространстве имён - сам или как часть составного типа.

- Заголовок: `#include <scl/utility/meta/tu_local.h>`
- Объявление:

```cpp
template <typename T> struct is_tu_local;                    // : std::bool_constant<...>
template <typename T> inline constexpr bool is_tu_local_v;   // = is_tu_local<T>::value
```

### Семантика

Маркер анонимного пространства имён выводится на этапе компиляции. Имя пробного типа,
объявленного в анонимном пространстве имён, сравнивается с именем такой же пробы с внешним
связыванием; то, чем они различаются, и есть маркер, который затем ищется в имени `T`. Маркеров
выводится два, потому что MSVC пишет его по-разному для типа верхнего уровня и для типа внутри
аргумента шаблона. Вывод вместо готового списка оставляет проверку работоспособной и на
компиляторе, который никто не испытывал.

Маркер принимается в любом месте строки за пределами строковых и символьных литералов, поэтому
составные типы тоже покрыты: указатель на локальный тип, ссылка на него и специализация шаблона
по нему сами локальны. Строковый или символьный параметр шаблона пишется внутри литерала в
кавычках, на MSVC - кодами символов, а содержимое литералов при поиске пропускается. Поэтому
параметр, в котором встречается текст маркера, не отнесёт внешний тип к локальным.

### Пример

```cpp
#include <scl/utility/meta/tu_local.h>
#include <vector>

namespace { struct duck {}; }
struct goose {};

static_assert(scl::is_tu_local_v<duck>);
static_assert(scl::is_tu_local_v<duck *>);
static_assert(scl::is_tu_local_v<std::vector<duck>>);
static_assert(!scl::is_tu_local_v<goose>);
static_assert(!scl::is_tu_local_v<int>);
```
