# Измерение оптимизационных атрибутов

Как измеряется действие `SCL_FORCE_INLINE`, `SCL_HOT` и подсказок ветвления и что показали
измерения по всем аннотируемым группам. Подробности по группам:
[hash](../hash/benchmark.md), [flags](../flags/benchmark.md),
[hierarchy](../hierarchy/benchmark.md).

## Условия

| | |
|---|---|
| Время | GCC 16.0.1 и Clang 22.1.8, x86-64 Linux, Release (`-O3`), 16 ядер по 2304 МГц |
| | MSVC 19.44.35228 (Visual Studio 2022), x64 Windows, Release |
| Размер кода | GCC 13.2.1, `arm-none-eabi`, Cortex-M4, `-Os` (`MinSizeRel`) |
| Повторы | 20, только агрегаты |

## Воспроизведение

```sh
script/ci/build.sh clang-x64 Release -DSCL_BUILD_BENCHMARKS=ON -DSCL_BUILD_TESTS=OFF
SCL_BENCHMARK_TAG=baseline SCL_BENCHMARK_REPETITIONS=20 script/ci/run_benchmarks.sh clang-x64

cmake --preset arm-none-eabi -DSCL_BUILD_BENCHMARKS=ON && cmake --build --preset arm-none-eabi
script/ci/run_size.sh arm-none-eabi
```

Каждый прогон записывается в JSON в `build/<preset>/benchmark-results/`;
`SCL_BENCHMARK_TAG` даёт ему имя, чтобы пара пережила переключение ветки.
`3rdparty/benchmark/tools/compare.py` читает два таких файла и добавляет проверку
значимости, если доступны `numpy` и `scipy`.

## Методика

Атрибут сравнивается с тем же кодом без него, по одному атрибуту и по одной группе за раз.
База не несёт ни одного оптимизационного атрибута нигде, поэтому испытуемая группа
стартует из того же состояния, что и остальные.

Значимость разницы определяют четыре правила.

**Разброс внутри прогона не является порогом.** Каждая ячейка матрицы измеряет все три
группы, хотя её патч затрагивает одну. Патч по `flags` оставляет двоичный файл `hash`
нетронутым, поэтому такие ячейки многократно измеряют один и тот же файл и показывают
вклад одной только машины. Этот разброс в несколько раз шире коэффициента вариации,
который Google Benchmark сообщает внутри прогона: `fnv1a_string_view` под GCC даёт от 40.6
до 42.3 нс по семи ячейкам, собранным из одинаковых исходных текстов, тогда как
коэффициент вариации внутри каждой остаётся ниже 1%. Разница меньше межпрогонного разброса
результатом не является.

**Уцелевшая разница перепроверяется чередованием.** Оба двоичных файла сохраняются и
измеряются по очереди, несколько раз подряд. Разница, принадлежащая файлу, повторяется в
каждом чередовании; разница, принадлежащая состоянию машины, - нет.

**Уцелевшая разница изолируется контролем.** Атрибут применяется ко всем функциям группы,
кроме той, чей случай сдвинулся. Если случай сдвигается и без неё, причина в другом - в
раскладке кода или в соседней функции того же двоичного файла.

**Слишком шумные случаи называются, а не приводятся.** `hierarchy_walk_recursive` держит
коэффициент вариации от 5.7 до 7.4% при 20 повторах и сдвинулся на 14% между двумя
ячейками, собранными из одинаковых исходных текстов. Он не выдерживает вывода того
масштаба, в котором работают эти атрибуты. Случаи, укладывающиеся в наносекунду,
сворачиваются против входа времени компиляции и измеряют оснастку, а не операцию.

## Во что раскрываются макросы

Два из них на MSVC определены пустыми, поэтому измерение там показало бы одну лишь машину.

| Макрос | GCC, Clang | MSVC |
|---|---|---|
| `SCL_FORCE_INLINE` | `[[gnu::always_inline]] inline` | `__forceinline` |
| `SCL_HOT` | `[[gnu::hot]]` | пусто |
| `SCL_LIKELY` / `SCL_UNLIKELY` | `[[likely]]` / `[[unlikely]]` | `[[likely]]` / `[[unlikely]]` |
| `SCL_LIKELY_EXPR` / `SCL_UNLIKELY_EXPR` | `__builtin_expect` | `(!!(expr))` |

## Результаты

Каждая запись, отличная от «нет эффекта», прошла чередование и контроль. Проценты - против
неаннотированной базы той же группы.

| Группа | Атрибут | GCC 16 | Clang 22 | MSVC 19.44 |
|---|---|---|---|---|
| hash | `SCL_FORCE_INLINE` | нет эффекта | `fnv1a_char_array` **-5.8%**, `siphash` **-6.4%** | `siphash` **-9%** |
| hash | `SCL_HOT` | нет эффекта | `siphash` **-5.5%** | определён пустым |
| hash | `SCL_UNLIKELY` | нет эффекта | `siphash` **-6.1%** | `siphash` **-16.5%** |
| flags | `SCL_FORCE_INLINE` | нет эффекта | `flags_iterate` **+43%** | нет эффекта |
| flags | `SCL_HOT` | нет эффекта | нет эффекта | определён пустым |
| flags | `SCL_LIKELY_EXPR` | `flags_all` **+7%** | нет эффекта | определён пустым |
| hierarchy | `SCL_FORCE_INLINE` | нет эффекта | нет эффекта | нет эффекта |
| hierarchy | `SCL_HOT` | нет эффекта | нет эффекта | определён пустым |
| hierarchy | `SCL_LIKELY` / `SCL_UNLIKELY` | нет эффекта | `is_ancestor_of` **+28%** | нет эффекта |

Размер кода, `.text` библиотек `*_size` на `-Os`, с `SCL_FORCE_INLINE` против без него:

| Группа | без | с |
|---|---|---|
| hash | 1950 | 3690 (+89%) |
| flags | 452 | 480 (+6%) |
| hierarchy | 84 | 84 |

`SCL_ASSUME` в таблице нет. Ни одна группа не даёт инварианта, который оптимизатор не
выводит сам, поэтому измерять нечего.

## Что означают результаты

**Ни один атрибут не помогает всем компиляторам, а три из них обходятся дороже отдачи хотя
бы на одном.** Два самых крупных найденных эффекта - регрессии: принудительное встраивание
обхода `flags` стоит 43% под Clang, а подсказки на ветках `is_ancestor_of` - 28% там же.
На двух других компиляторах ни того, ни другого нет.

**Единственная окупающаяся подсказка ветвления зависит от компилятора и велика.** `siphash`
заполняет восьмибайтовый блок раз в восемь итераций; пометка этой ветки как маловероятной
даёт 16.5% под MSVC, 6% под Clang и ничего под GCC. Аппаратный предсказатель справляется с
этим шаблоном без помощи, поэтому выигрыш возникает из того, как компилятор располагает и
планирует два пути, а не из точности предсказания.

**`SCL_FORCE_INLINE` бесплатен на `-O3` и дорог на `-Os`.** На `-O3` и GCC, и Clang уже
встраивают аннотированные тела, а определение `SCL_FORCE_INLINE=inline` даёт побайтово
совпадающий код. На `-Os` компилятор встраивает неохотно, аннотация это переопределяет, и
поверхность `hash` вырастает на 89%. Цену аннотации платит только сборка, ограниченная по
размеру, то есть ровно та, которая может определить макрос пустым.

## Целесообразность применения

Атрибут применяется, когда он даёт выигрыш хотя бы на одном поддерживаемом компиляторе и
не проигрывает ни на одном. Цена в размере кода не запрещает применение, поскольку
сборка, которая не может её позволить, определяет макрос пустым; цена в скорости
запрещает, поскольку по умолчанию выбрана скорость и вернуть её нечем.

| Группа | Атрибут | Применён | Почему |
|---|---|---|---|
| hash | `SCL_FORCE_INLINE` | **да** | даёт выигрыш на Clang и MSVC, бесплатен на GCC; размер стоит только на `-Os` и снимается переопределением |
| hash | `SCL_UNLIKELY` | **да** | самый крупный измеренный выигрыш, на двух компиляторах, без потерь на третьем и без цены в размере |
| hash | `SCL_HOT` | нет | единственный эффект - на том же случае, который `SCL_UNLIKELY` улучшает сильнее, а поверх этой подсказки он не даёт ничего |
| flags | `SCL_FORCE_INLINE` | нет | отнимает 43% на единственном случае с реальной работой и не даёт ничего нигде |
| flags | `SCL_LIKELY_EXPR` | нет | отнимает 7% под GCC и не даёт ничего нигде |
| flags | `SCL_HOT` | нет | нет эффекта ни на одном компиляторе, который его реализует |
| hierarchy | `SCL_LIKELY` / `SCL_UNLIKELY` | нет | отнимает 28% под Clang и не даёт ничего нигде |
| hierarchy | `SCL_FORCE_INLINE`, `SCL_HOT` | нет | нет эффекта ни на одном компиляторе, размер кода не меняется |
| все группы | `SCL_ASSUME` | нет | нет места применения: любой доступный инвариант оптимизатор выводит сам |

Из девяти строк выигрыш дают две, шесть означают потерю или отсутствие эффекта, ещё одна
дублирует лучшую. Значит оптимизационный атрибут целесообразен лишь там, где это
показывает измерение для конкретной функции на конкретном компиляторе, и никогда - как
политика, применённая ко всей поверхности.

## Обмен скорости на размер

Каждый атрибутный макрос защищён собственным `#ifndef`, поэтому сборка переопределяет те,
которые не может себе позволить:

```sh
cmake --preset arm-none-eabi -DCMAKE_CXX_FLAGS=-DSCL_FORCE_INLINE=inline
```

По умолчанию выбирается скорость. Сборка, которой нужен меньший образ, запрашивает его
явно, а числа выше говорят, чем она за это платит.
