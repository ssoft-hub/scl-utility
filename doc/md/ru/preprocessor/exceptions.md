# Доступность исключений

Сообщает, скомпилирована ли единица трансляции с исключениями, и управляет объявлением тех
сущностей ScL, которые сообщают о неудачном запросе через исключение.

- Заголовок: `#include <scl/utility/preprocessor/exceptions.h>`

Содержание:
- [`SCL_HAS_EXCEPTIONS`](#scl_has_exceptions)

---

## `SCL_HAS_EXCEPTIONS`

Раскрывается в `1`, если единица трансляции скомпилирована с исключениями, иначе в `0`.

- Заголовок: `#include <scl/utility/preprocessor/exceptions.h>`
- Объявление: `#define SCL_HAS_EXCEPTIONS /* 1 или 0 */`

### Семантика

- **Определён всегда:** проверять через `#if`, а не через `#ifdef`. Тогда опечатку в имени
  сообщит `-Wundef`, а не молчаливое вычисление в ложь.
- **Выводится по компилятору:** `_CPPUNWIND` (MSVC), `__EXCEPTIONS` (GCC и Clang) либо
  `__has_feature(cxx_exceptions)` (Clang). Стандартного макроса проверки этой возможности
  язык не определяет — ради этого макрос и существует.
- **Это отчёт, а не переключатель:** определение его вручную не включает и не выключает
  исключения. Он сообщает то, что компилятору передали в командной строке.
- **Что он закрывает в ScL:** четыре перегрузки `scl::any_cast`, возвращающие значение или
  ссылку, объявлены только там, где он равен `1` — см. [`any_view`](../any/any_view.md) и
  [`any_arg`](../any/any_arg.md). Перегрузки, возвращающие указатель, остаются и отвечают
  на неудачный запрос значением `nullptr`.
- **`scl::flags`:** порядковый номер перечислителя `>= bit_count` — это нарушение
  предусловия, а не запрос, ответивший отказом, и вернуть вместо него нечего. Там, где
  макрос равен `0`, такой вызов завершает программу через `std::abort()` вместо выброса
  `std::out_of_range`. В вычислениях времени компиляции он некорректен в обоих случаях.

### Примеры

```cpp
#include <scl/utility/any.h>
#include <scl/utility/preprocessor/exceptions.h>

std::string const & text(scl::any_view const & view)
{
#if SCL_HAS_EXCEPTIONS
    return scl::any_cast<std::string const &>(view);
#else
    return *scl::any_cast<std::string>(&view);
#endif
}
```

Код, который должен собираться в обеих конфигурациях, обходится одной указательной формой —
она объявлена в обеих:

```cpp
#include <scl/utility/any.h>

bool is_empty_string(scl::any_view const & view)
{
    auto const * text = scl::any_cast<std::string>(&view);
    return (text != nullptr) && text->empty();
}
```

## Примечания

- `scl::bad_any_cast` объявлен в обеих конфигурациях. Исчезают только перегрузки, которые
  его выбрасывают, поэтому `catch` по этому типу собирается везде, где до него можно дойти.
- [`SCL_HAS_RTTI`](rtti.md) — то же самое для RTTI, и эти два макроса независимы: любая
  конфигурация одного доступна при любой конфигурации другого.
